Event-Based Obstacle Sensing and Avoidance for an UAV Through Deep Reinforcement Learning

事件相机 + 变分自编码器 + PPO：直接处理"事件流"而非"事件帧"的高速感知规避

作者Xinyu Hu（胡新宇，第一作者）、Zhihong Liu（刘志宏，通讯）、Xiangke Wang（王祥科）、Lingjie Yang（杨凌杰）、Guanzheng Wang（王冠政，第五作者）
单位国防科技大学（National University of Defense Technology, Changsha）
会议CICAI 2022（第二届中国人工智能学会国际会议），Springer LNAI 13606, pp. 402–413；DOI: 10.1007/978-3-031-20503-3_32（全文收录于本地 978-3-031-20503-3.pdf 论文集第 402–413 页）
一句话事件相机能以微秒级响应亮度变化，天生适合高速避障；但事件流是稀疏、异步、长度不定的，不能像图像那样直接喂 CNN。本文用事件上下文编码网络（ECEN，含 VAE）把任意长度的事件流压成 1024 维潜向量，再交给 PPO 输出连续速度指令；数据在 AirSim + Unreal Engine 4 里用 RRT* 自动采集，最终在 AirSim 中做到实时避障，成功率优于离散动作的基线。
Event Camera VAE / ECEN PPO（连续动作） AirSim + UE4 event-sim 插件 RRT* 数据采集

2. 核心洞察与创新点

🎯 核心洞察：不要"攒帧"，要"读流" 绝大多数事件相机 + 学习的做法是把事件累积成"事件帧"（event frame），再当普通图像处理。但这等于把事件相机最宝贵的两个特性扔掉了：微秒级时间分辨率（被帧率重新量化）与稀疏性（被稠密化）。本文坚持对每一个事件直接运算，用 PointNet/EventNet 式的点集特征 + Transformer 时间聚合 + VAE 降维，得到与事件流长度无关的固定维潜向量。好处是可以适应任意控制频率——事件来得快就多算，来得慢就少算，而不是被固定帧率卡死。
第二层洞察：把"感知"与"决策"分成两段训练，各自用最合适的工具 感知段（ECEN）用自监督：VAE 的 decoder 要重建事件图，encoder 因此必须保留几何信息——不需要人工标注。决策段用PPO：固定 ECEN 权重，只训 actor-critic。这样 RL 的样本效率问题被隔离在一个低维潜空间里，而不是让 RL 直接啃原始事件流。

2.1 创新点拆解

创新点做法解决什么
① 直接处理事件流输入单个事件序列（长度可变），而非累积帧；时间维度用 Transformer 聚合保留微秒级时间分辨率与稀疏性；可适应变控制频率
② ECEN（事件上下文编码网络）三组 dense 层 → 1024 维时空特征 → 两层卷积 → 潜向量；decoder 用三层卷积重建事件图把任意长度事件流压成定长、平滑、连续的表示，作为 RL 的观测
③ 连续动作空间 PPO输出 $[v_x,v_y]$ 二维连续速度，替代基线的离散动作离散动作无法平滑调整，高速场景下抖动大；连续动作显著提升平均奖励（50 → 190）
④ 全流程在 AirSim 中自采集用 RRT* 控制无人机在仿真走廊中飞 100 次，采集 100 条事件流；AirSim 的 event-sim 由两张连续 RGB 图算事件免去真实事件相机的昂贵采集；同时保留 UE4 的光照/材质真实性

4. 任务定义

事件生成模型（DVS 原理） $$ L(x,y,t)-L(x,y,t-\Delta t)\ \ge\ p\,C \;\Longrightarrow\; \text{在该像素生成事件 } e_k=(x_k,y_k,t_k,p_k) $$ $$ E_\tau=\{e_k\}_{k=1}^{N}=\{(x_k,y_k,t_k,p_k)\}_{k=1}^{N} $$
$L$ = 对数亮度 | $C$ = 阈值（本文 TOL=0.1） | $p\in\{-1,1\}$ = 极性（亮度变亮/变暗） |  $E_\tau$ = 一段事件流，长度 $N$ 可变——这正是后续网络必须"与长度无关"的原因。
要素内容
输入连续三帧潜向量 $z_t,z_{t-1},z_{t-2}$（每帧来自一段事件流的编码）
输出$[v_x,v_y]$ 二维连续速度指令
奖励$r=r_g+r_c$：$r_g$ 为到达奖励（距离 < 1 m 得 $r_{arrival}$，否则按距离减少量给 $k_d$）；$r_c$ 为碰撞惩罚——碰撞状态由 AirSim 的回调直接给出（原文："it depends on the callback from Airsim"）
场景边长 >100 m 的长走廊，密集障碍；起点/终点区域明确；目标区域到达即成功
对照discrete baseline（同代码同超参的离散动作版）、discrete proposed（改奖励）、continuous proposed（改连续动作 + 新奖励）

5. 挑战分析

为什么"事件相机 + RL"比"RGB + RL"难 ① 数据结构不规整。事件流是 $(x,y,t,p)$ 的四元组集合，长度随场景动态变化（1000～4000 个事件），没有"图像"的网格结构，标准 CNN 用不上。
② 稀疏性悖论。攒成帧能稠密化，但会丢掉微秒级时序；不攒帧则输入维度不定，且大部分像素为空。
③ 仿真支持差。主流仿真器（Gazebo/Stage）没有事件相机模型；必须靠"渲染两张连续 RGB → 差分生成事件"的近似（AirSim 的 event-sim），这要求渲染器足够真实。
④ 奖励稀疏 + 高速。高速飞行下回合短、碰撞惩罚强，探索极难；本文靠"接近增量"奖励和 500 回合预算才训起来。

5.1 为什么必须用 AirSim / Unreal，而不能用 Stage 或 Gazebo

这是全篇最关键的仿真器论点 事件相机测量的是"亮度变化"，因此它需要真实的光照与材质。Stage 是 2D 栅格（无光照），Gazebo 的 OGRE 渲染在材质与光照真实性上远不及 UE4——用它们生成的"事件"会与真实事件相机的统计特性相差极大。

换句话说：仿真器的选择由传感器模态决定。做 LiDAR 避障时（6202/6205）用 Stage 最划算，因为 LiDAR 只关心几何；做事件相机时，几何够用但光度不够，必须上 UE4。这条判据可以直接迁移到任何"传感器驱动的仿真器选型"。

6. 方法与核心公式

6.1 ECEN：把变长事件流压成定长潜向量

编码—解码（VAE 结构） $$ z=\mathrm{Enc}_\phi(E_\tau),\qquad \hat E=\mathrm{Dec}_\psi(z),\qquad \mathcal{L}_{\text{VAE}}=\mathbb{E}\big[\lVert \hat E-E_\tau\rVert^2\big]+\beta\,\mathrm{KL}\big(q_\phi(z\mid E_\tau)\,\Vert\,p(z)\big) $$
$E_\tau$ 长度可变（1000–4000 事件） | $z$ 定长潜向量，作为 RL 的观测 |  $\mathrm{KL}$ 项让潜空间平滑连续——这对 RL 很关键：相邻时刻的观测不会突变，策略学起来稳定 |  重建项提供自监督信号，不需要人工标注"哪里是障碍"。

6.2 PPO 目标（含 KL 自适应惩罚）

Algorithm 1 的核心式 $$ J^{PPO}(\theta)=J^{\theta_k}(\theta)-\beta\,\mathrm{KL}(\theta,\theta_k),\qquad J^{\theta_k}(\theta)\approx\sum_{(s_t,a_t)}\mathrm{ratio}\cdot A^{\theta_k}(a_t,s_t) $$ $$ \mathrm{ratio}=\frac{p_\theta(a_t\mid s_t)}{p_{\theta_k}(a_t\mid s_t)}\ \text{并裁剪到}\ [1-\epsilon,\,1+\epsilon] $$
$\beta$ 随实际 KL 自适应调整（"adaptive penalty coefficient on KL divergence"）；$\epsilon$ = clip range。 算法流程：交互采 $\{s_t,a_t,r_t\}$ → 算优势 → 每 $n_{step}$ 步做 $n_{epoch}$ 轮更新 → 若 KL 超 target 则提前 break。

7. 仿真器专题——AirSim + UE4：为什么要"贵"的那一个

这是六篇里唯一必须用高保真渲染的工作，也是他仿真器谱系里最"反直觉"的一个选择——因为在 6201/6205 里，渲染恰恰是被关掉的。

7.1 为什么选 AirSim

理由具体
事件相机需要光度真实事件是亮度变化的函数。UE4 的 PBR 材质、全局光照、动态阴影，让"两张连续 RGB 的差分"接近真实事件相机的输出分布。这是 Gazebo/Stage 给不了的。
有现成的事件相机插件AirSim 用 Python 从两张连续 RGB 计算事件，封装为 event-sim 扩展包，分辨率与 TOL 可调——不用自己写传感器模型。
碰撞检测可直接调用奖励里的 $r_c$ 直接来自 AirSim 的碰撞状态回调（原文："depends on the callback from Airsim"），免去自己写碰撞查询。
场景可编辑长走廊 + 密集障碍的 scene 在 UE 编辑器里搭，比 Gazebo 的 SDF 拼装直观得多。
Python API 友好与 SB3/RL 循环的胶水成本低。

7.2 好在哪

  • 传感器真实性最高：对"感知型"研究（事件相机、视觉、深度），渲染真实性直接决定结论能否外推。
  • 端到端闭环：采集 → 训练 → 验证都在同一个 AirSim 世界，无需跨仿真器迁移（对比 6202 的双栈）。
  • 可复现的开源栈：AirSim（已归档但代码可得）+ event-sim + SB3，论文还给了代码与数据集地址。

7.3 有什么问题

最根本的一条：训练与验证在同一个仿真器、甚至同一个场景里 论文的验证实验"使用的仿真设置（硬件、初始化、参数）与训练环境完全相同"——这意味着测的是拟合能力，不是泛化能力。对事件相机这种"仿真到现实落差极大"的传感器，这恰恰是最需要检验的地方。
问题说明影响
① 无 sim-to-real全部实验在 AirSim 内；没有真实事件相机数据，也没有真实事件相机在环测试★★★★★ 事件相机的仿真-现实差距（噪声、阈值漂移、 refractory period）是公认最大的，论文完全未触及
② 事件模型是近似的用"两张连续 RGB 差分"生成事件，本质是帧率采样的近似，丢掉了真实 DVS 的异步性与微秒精度★★★★ 那么"直接处理事件流"的主张在仿真里其实并未真正被检验——仿真事件仍来自帧
③ 训练/验证同场景同一走廊、同一初始化★★★★ 无法排除过拟合
④ 2D 动作 + 定高动作只有 $[v_x,v_y]$，无高度控制★★★ 事件相机的价值在高速机动，而定高飞行限制了这个价值
⑤ 数据量小100 条事件流；ECEN 的训练数据规模有限★★★ 潜空间的泛化性受限，换场景很可能失效
一句话总结 用"贵"的 AirSim + UE4 换传感器的光度真实性，用"帧差分"近似换实现成本，用"同场景验证"换干净的对照。代价是——这篇论文证明了"方法可行"，但没有证明"方法在真实事件相机上可行"。

9. 不足与扩展方向

9.1 局限性

  • 缺"事件流 vs 事件帧"的关键对照：全文最核心的主张（直接处理流优于攒帧）没有被直接实验验证。
  • 同场景训练与测试：没有跨场景泛化实验（不同走廊宽度、不同障碍密度、不同光照）。
  • 无真实事件相机：没有 DAVIS/DVS 实测数据，无法评估仿真事件的真实性。
  • 动作空间只有平面速度：没有姿态/高度，无法体现事件相机在高速机动中的优势。

9.2 值得深挖的方向

  1. 补一个"帧 vs 流"的消融：同一 ECEN 容量下，输入换成事件帧 + 同等参数量的 CNN，比较成功率与延迟——这是能把论文从"可行"提升到"有说服力"的最小改动。
  2. 事件仿真器的真实性校准：用真实 DVS 数据（如 RPG 的 event camera dataset）标定 TOL、噪声率、refractory period，再回头看策略是否还成立。
  3. 把"流"的优势用在控制频率上：论文提到"可适应变控制频率"，但没有做实验。设计一个"控制频率 100 Hz vs 1 kHz"的对照，才能证明这个特性有价值。
  4. 与 6201 的"渲染可关"结合：训练前期关渲染用廉价几何仿真学"往哪飞"，后期开渲染学"事件长什么样"——两阶段能省下大量 UE 渲染时间。

10. 动机推导

一句话动机 想让无人机在高速下避障，传统相机 30–60 Hz 的采样太慢、动态范围太窄；事件相机快得多，但它的输出不是图像——所以要么改造数据（攒帧，丢掉优势），要么改造网络（直接读流，保住优势）。本文选了后者。

10.1 推导链

  1. 痛点：高速飞行 → 需要高时间分辨率感知 → 传统帧相机的运动模糊与低动态范围成为瓶颈。
  2. 工具：事件相机（DVS）微秒级响应、高动态范围、低功耗——天生适合高速避障。
  3. 障碍：事件流是变长稀疏点集，CNN 无法直接用；攒成帧又会把时间分辨率退回到帧率。
  4. 解法：用"点集编码（dense/PointNet 思路）+ Transformer 时间聚合 + VAE 降维"得到定长潜向量，让下游 RL 只面对低维连续观测。
  5. 验证：在 AirSim（唯一能提供真实光度的开源仿真器）里用 RRT* 采数据、PPO 训策略，逐级消融"奖励 → 动作空间"。

11. 关键启示

11.1 方法论

  • 仿真器选型的第一问是"传感器需要什么"：几何 → Stage/Gazebo 足够；光度 → 必须 UE/AirSim。这条判据比"哪个仿真器更先进"有用得多。
  • 感知与决策分开训：自监督学表示、RL 学策略。这样 RL 的样本效率问题被限制在低维潜空间里。
  • 消融要有"阶梯"：奖励 → 动作空间逐级加，每一步的增益都可见（+85 / +55）。

11.2 可直接迁移

  • 变长观测的编码：VAE + KL 正则让潜空间平滑，这个技巧对任何"异步/变长传感器"（事件、雷达点云、异步 IMU）都适用。
  • 用 RRT* 做数据采集：比随机飞更高效，且保证样本覆盖安全飞行区域——采集阶段的"专家"不必是最终策略。
  • 碰撞回调当奖励：仿真器自带的碰撞检测是最可靠的稀疏信号源，比自算几何更快更稳。
