2. 洞察与创新

2.1 核心洞察

🎯 核心洞察：不要"在 GPU 上跑仿真"，而要"把仿真器写成一张 PyTorch 计算图"

问：现有 GPU 四旋翼仿真器已经很快了（OmniDrones $8.4\times10^{5}$ FPS、Aerial Gym $1.9\times10^{6}$ FPS），为什么还需要重写一个？

答：因为它们"快"的边界被三件事卡住了。（i）引擎边界即计算图边界——PhysX / Warp / Unity / Habitat-Sim 都是 C++/CUDA 引擎，状态以张量形式暴露给 PyTorch，但"张量 → 引擎 → 张量"这一步天然切断了反向传播：你可以拿到 $\mathbf{s}_{t+1}$，却拿不到 $\partial \mathbf{s}_{t+1}/\partial \mathbf{a}_t$。（ii）动作语义不匹配——通用刚体引擎把动作定义为关节力矩（joint torque），而四旋翼的动作是"总推力 + 三轴机体角速率"（或期望加速度），要么在引擎外再套一层控制器（又多一层不可微），要么改引擎。（iii）渲染管线不可微且昂贵——光栅化（rasterization）在 64×64 这种极低分辨率下是"用牛刀杀鸡"，而且它只输出像素、不输出"像素对位姿的导数"。

本文的洞察因此是三条互相咬合的设计决策，而不是一个孤立的技巧：

  • 决策一（计算图完整性）：物理积分、传感器（IMU / 深度相机 / LiDAR）、奖励计算全部用 PyTorch 算子实现，中间不出现 NumPy、不出现 host 同步。于是"深度图上的一个奖励"到"电机指令"之间存在一条端到端可微路径——这正是论文敢说"first differentiable simulation framework that performs both physical simulation and visual rendering fully on the GPU"的底气。
  • 决策二（双奖励通道）：环境每个时间步同时返回可微 loss（可反传到动作）与不可微 reward（标量，供 RL 用）。这一个接口决定，让"纯 RL""纯可微""混合"三种范式共用同一个 env.step()——混合算法（SHA2C）才有可能在同一个循环里同时用上一阶梯度与零阶价值。
  • 决策三（保真度阶梯）：把动力学做成 4 档可插拔模型（full quadrotor → simplified → continuous point-mass → discrete point-mass），让"物理保真度"变成一个可调的超参数，而不是框架的固有属性。这直接对应论文 Fig. 8 的核心发现：保真度越高，优化地形越崎岖、收敛越慢。

为什么别人没这么做？因为"从零写一个引擎"在学术上的收益/风险比极差：通用引擎免费送你碰撞检测、约束求解、材质、场景编辑，代价是失去可微性与动作语义；而自研引擎一旦性能不如 Isaac 系，论文就只剩下"我们也做了一个仿真器"。作者赌的是：在"四旋翼 + 低分辨率深度 + 大规模并行 + 需要梯度"这个狭窄但极关键的交叉口上，通用引擎的全部优势都用不上，而它们的全部劣势都会被放大。Table I 与 Fig. 6 就是这场赌局的结算单。

2.2 灵感来源 → 洞察的映射

灵感来源→ 启发产生的洞察类型
Isaac Gym / OmniDrones / Aerial Gym（GPU 原生、状态即张量） → "状态直接是 PyTorch 张量、零拷贝"是正确方向，但它们止步于把引擎的输出接到张量上。DiffAero 把这个思路推到底：连引擎本身都用张量算子写，于是"零拷贝"升级为"零断图"——不仅数据不搬，梯度也不断。 架构
Brax / Warp / DiffTaichi（可微物理引擎） → 可微物理的威力已被证明，但它们面向通用刚体 + 关节力矩，与四旋翼的"推力/角速率"语义错位；且它们不同时可微渲染。DiffAero 放弃通用性，只为四旋翼写 4 个专用动力学，换来"动力学 + 传感器"同一条可微链。 方法
SHAC（Xu et al., ICLR 2022，短视界 + 终端价值） → 若奖励必须处处可微，那么"成功/失败""通过门"这类稀疏、离散、不可微的目标就永远进不了可微学习。SHAC 用 critic 估计终端价值来吸收这部分信号；DiffAero 进一步把它做成非对称 actor-critic（actor 只看局部观测，critic 看全状态），即 SHA2C。 算法
Zhang et al., Nat. Mach. Intell. 2025（质点动力学 + 可微物理做视觉敏捷飞行） → 把姿态自由度整个丢掉、只优化质心运动，可以让梯度穿过动力学时"又平滑又便宜"。DiffAero 把这一"降维换梯度"的策略产品化为 continuous / discrete 两档 point-mass 模型，并把"姿态从速度方向反解"写成一个显式函数 point_mass_quat()。 方法 / 数据
Flightmare / VisFly（视觉仿真 + 无人机） → 视觉是端到端飞行的必需品，但光栅化 + RAM↔VRAM 搬运会把吞吐锁死在 I/O 上（VisFly 的 GPU 并行在 Table I 中被特别标注为"(!)"）。反推：在 64×64、几十个基元的场景里，解析光线投射（ray casting）才是"计算量正比于有效光线数"的正确算法。 算法 / 工程
DreamerV3（世界模型） → 若框架自称"学习算法基准"，就必须容纳不依赖环境可微性、也不依赖大量真实交互的第三条路线。DreamerV3 在 Fig. 7 中作为"用更少数据但更多更新"的对照组出现，反衬出可微算法的样本效率优势。 评估
PX4 / ROS / ONNX（部署栈惯例） → 仿真器的价值最终由"策略能否飞起来"结算。DiffAero 把观测函数与策略一起导出为 ONNX（obs_fn.onnx + policy.onnx），让 ROS 节点只做推理，避免"训练用 Python 张量、部署用 C++ 手写"的语义漂移。 工程

⚠ 一个容易读错的细节：loss 与 reward 是同一组物理量的两种符号约定
在 env/obstacle_avoidance.py::loss_and_reward() 中，total_loss 是各项惩罚的加权和（越小越好），total_reward 则是 constant − Σ wᵢ·ℓᵢ 并立即 .detach()。也就是说：可微通道优化的是"惩罚的负梯度"，RL 通道优化的是"标量奖励的期望"；两者的权重表在配置里是分开的（loss_weights 与 reward_weights），因为正如论文 §IV-B 所说——"RL 算法对奖励的幅值敏感，可微算法只受奖励导数影响"。这是本文在工程上最容易被忽略、但在复现时最容易翻车的一处。

4. 任务定义——解决的问题是什么？

4.1 问题形式化：一个被"显式建模"的 POMDP

DiffAero 并不解决某一个任务，而是把"四旋翼策略学习"抽象成一个可参数化的部分可观测马尔可夫决策过程（POMDP），再用配置在三个任务上实例化它。形式化如下：

Eq.(T1) —— POMDP 六元组 $$ \mathcal{M} = \big\langle \mathcal{S},\, \mathcal{O},\, \mathcal{A},\, \mathcal{T},\, \Omega,\, R \big\rangle,\qquad \mathbf{s}_{t+1}\sim \mathcal{T}(\cdot\mid \mathbf{s}_t,\mathbf{a}_t),\quad \mathbf{o}_t\sim \Omega(\cdot\mid \mathbf{s}_t),\quad r_t = R(\mathbf{s}_t,\mathbf{a}_t) $$
$\mathcal{S}$ = 全状态空间（点质量模型 9 维，全四旋翼 13 维） |  $\mathcal{O}$ = 观测空间（策略可见的部分，含外感受量） |  $\mathcal{A}\subset[-1,1]^{3}$ = 归一化动作（连续） |  $\mathcal{T}$ = 由 dynamics/*.py 的 RK4/Euler 积分定义的转移核，完全可微 |  $\Omega$ = 传感器模型（深度/LiDAR/IMU，含噪声与安装误差） |  $R$ = 任务奖励。
关键点在于：$\mathcal{T}$ 与 $\Omega$ 不是黑箱，而是由可微算子显式给出的函数，因此这个 POMDP 同时具备"采样器"与"求导器"两种身份——这正是第 6、7 节所有算法的基础。

在这之上，框架同时定义两个优化目标，它们共享同一个 rollout，却用不同的梯度通道：

Eq.(T2) —— 两通道目标（RL 通道 vs 可微通道） $$ \max_{\theta}\; J_{\text{RL}}(\theta)=\mathbb{E}_{\pi_\theta}\Big[\textstyle\sum_{t=0}^{T-1}\gamma^{t}\,r_t\Big], \qquad \min_{\theta}\; J_{\text{diff}}(\theta)=\mathbb{E}_{\pi_\theta}\Big[\textstyle\sum_{t=0}^{T-1}\ell\big(\mathbf{s}_t,\mathbf{a}_t\big)\Big] $$
$r_t$ = 标量奖励（total_reward，已 detach，不参与对动作的求导） |  $\ell(\cdot)$ = 可微惩罚（total_loss，直接由状态与动作的可微函数给出） |  为什么需要两个：$r_t$ 可以是稀疏、离散、不可微的（"是否通过门""是否到达"），$\ell$ 必须是稠密、连续、可微的（"距离""速度误差""接近障碍物的速度惩罚"）。二者不能互相替代：只有 $\ell$ 会使策略陷入局部最优（等价于人工势场法），只有 $r_t$ 则样本效率极低。SHA2C 的全部巧思就是把两者拼起来（见 6.3）。

4.2 观测 / 动作空间

框架的观测被拆成 TensorDict{state, perception} 两部分：标量状态向量走 MLP/RNN，图像走 CNN。默认 obs_frame: "local"——即观测、动作都在"只保留偏航"的局部系中表达（BaseDynamics.Rz = Rz(yaw)），这样策略天然对偏航不变，是论文 §IV-D 所述 sim-to-real 的关键设计之一。

4.3 奖励 / 损失的具体构成

Eq.(T3) —— 避障任务的可微损失（点质量模型） $$ \ell_t \;=\; w_{\text{vel}}\,\ell_{\text{vel}} + w_{z}\,\ell_{z} + w_{\text{oa}}\,\ell_{\text{oa}} + w_{\text{jerk}}\,\ell_{\text{jerk}} + w_{\text{pos}}\,\ell_{\text{pos}} + w_{\text{col}}\,\ell_{\text{col}} $$ $$ \ell_{\text{pos}} = 1-e^{-\|\mathbf{p}-\mathbf{p}_g\|},\quad \ell_{z}=1-e^{-|p_z-p_{g,z}|},\quad \ell_{\text{col}}=\mathbb{1}\big[d_{\text{obs}}<r_{\text{drone}}\big] $$
权重取自 cfg/env/oa.yaml:25-33：$w_{\text{vel}}=2,\;w_z=1,\;w_{\text{oa}}=5,\;w_{\text{jerk}}=0.01,\;w_{\text{pos}}=5,\;w_{\text{col}}=0$。
$\ell_{\text{pos}}=1-e^{-d}$ 是一个"饱和距离"——近距离时梯度约为 $-1$（线性收敛），远距离时梯度趋于 0（不再盲目加速），比直接用 $d$ 或 $d^2$ 更不容易在远端产生爆炸梯度。$\ell_{\text{col}}=0$ 说明碰撞不进入可微损失（它是不可微的指示函数，且碰撞即终止，梯度无意义），而只在 terminated() 里截断回合——这正是"可微通道必须放弃不可微信号"的教科书例子。
Eq.(T4) —— 可微的避障惩罚项（全文最"讲究"的一项） $$ d^{\text{inf}}_i=\max\!\big(d_i-(r_{\text{drone}}+\delta),\,0\big),\quad \kappa_i=e^{-d^{\text{inf}}_i},\quad v^{\text{app}}_i=\big\langle \hat{\mathbf{n}}_i,\mathbf{v}\big\rangle $$ $$ \ell_{\text{oa}} = \max_i\big[\mathbb{1}(v^{\text{app}}_i>0)\,v^{\text{app}}_i\,\kappa_i\big] \;-\;0.5\,\mathbb{1}(v^{\text{app}}_i>0)\,\big\|\mathbf{v}-v^{\text{app}}_i\hat{\mathbf{n}}_i\big\|\,\kappa_{i^\ast} $$
$d_i$ = 到第 $i$ 个障碍物表面的最近距离 |  $\delta=0.2$ m = 安全膨胀量（代码 inflation=0.2） |  $\kappa_i$ = "危险度"，距离越近越接近 1 |  $v^{\text{app}}_i$ = 沿"指向障碍物"方向的接近速度，$>0$ 表示正在撞上去 |  $i^\ast$ = 最危险的那个障碍物下标。
物理含义：第一项惩罚"离得近 + 朝它飞"，第二项奖励"离得近 + 侧向掠过"（切向速度的 $0.5$ 倍）。这实际上把"避障"写成了一个可微的、连续的人工势场，但只对最危险的单个障碍物生效（.max(dim=-1)），避免了 30 个障碍物求和导致的"惩罚项被稀释"。env/obstacle_avoidance.py:160-177
Eq.(T5) —— 标量奖励（RL 通道，detach 后使用） $$ r_t=\underbrace{c}_{\text{常数偏置}}-\sum_{k} \tilde{w}_k\,\ell_k(\mathbf{s}_t,\mathbf{a}_t)\;-\;\tilde{w}_{\text{arr}}\,\mathbb{1}\big[\|\mathbf{p}-\mathbf{p}_g\|\ge 0.5\big] $$
$c=2$（SHA2C 配置）或 $c=1$（纯 RL 配置）——一个与状态无关的正偏置，作用是让"活得久"本身就有正收益，防止策略学会"快速撞死以终止负奖励"。 |  $\tilde{w}$ = reward_weights，与 loss_weights 不同的一套数：例如 SHA2C 配置里 pointmass.vel/z/oa/pos 全部置 0，只保留 jerk: 0.001 与 collision: 50——即"梯度通道负责飞得准，标量通道只负责'别撞'"。 |  到达判定阈值 0.5 m 是代码里的硬编码（base_env.py:115）。

4.5 与相邻任务的边界

相邻任务与本任务的交集本质区别
轨迹跟踪（trajectory tracking）都要跟踪一个参考信号（这里是 $\mathbf{v}_{\text{target}}$）跟踪任务给定时变参考轨迹、目标是零误差；这里只给一个静态目标点，参考速度是"策略自己算出来的中间量"，且允许任意机动、只要最终到达并驻留。换句话说：跟踪是手段，到达才是目的。
端到端 RL 飞行（如 OmniDrones 基准）同样的"观测→动作"范式、同样的并行采样那些平台只能做零阶优化；DiffAero 的观测/动作完全相同，但额外暴露了 $\partial\ell/\partial\mathbf{a}$，于是同一任务可以在三种范式下比较（Fig. 7 的 BPTT/SHAC/SHA2C vs PPO/DreamerV3）。这是"基准平台"与"仿真器"的差别。
可微渲染 / 可微视觉伺服都需要 $\partial(\text{图像})/\partial(\text{位姿})$可微渲染的目标通常是"用图像监督反解几何"（逆渲染）；这里的深度图只是观测，梯度可以穿过它，但论文并未利用"图像对位姿的梯度"做监督——这是一个已铺好路却尚未走的方向（见 9.2）。
竞速（autonomous racing）同属"高速穿越"家族竞速的目标是时间最优，奖励天然稀疏且与"进度"强相关；论文坦承未能设计出有效的可微竞速奖励，故该任务上可微算法全部失效（§IV-B），实际由 PPO 主导——这恰好构成"可微方法边界"的实证。

5. 技术挑战——为什么困难？

5.1 本质分析（第一性原理诊断）

💡 第一性原理诊断：这是"三堵墙"同时收窄的工程问题

墙一：时间墙（吞吐）。无模型 RL 的样本复杂度大致是 $\mathcal{O}(\varepsilon^{-2})$ 量级，训练一个视觉飞行策略需要 $10^{8}\sim10^{9}$ 步交互。若仿真步进是 1 ms/步（单环境），完成 $10^{8}$ 步需要 27.8 小时——这还没有算渲染。想把它压到"小时级"，唯一出路是并行 + 每步常数极小。于是"每一步要启动多少 CUDA kernel、要做多少次 host-device 同步"成为一等公民，而不是工程细节。

墙二：图墙（可微）。反向传播要求前向的每个算子都是可微且数值良态的。而物理仿真里塞满了"坏"算子：碰撞是指示函数（几乎处处梯度为 0）、四元数归一化在原点奇异、max/min 会杀掉一部分梯度、if 分支会让图结构随状态变化。可微仿真器的难点不在"能不能求导"，而在"求出来的导数值不值得信"。

墙三：账墙（显存）。BPTT 的显存开销随 rollout 长度线性增长（要保存整条链的中间激活）。$N$ 个环境 × $T$ 步 × 每步激活量，在 1024 环境 × 32 步的量级上就会吃掉数 GB。这与"墙一"直接冲突：想更快就要更多环境，更多环境就要更多显存，更多显存就限制了 rollout 长度。

三墙交汇处：一个既要 $10^{6}$ FPS 吞吐、又要端到端可微、还要在 24 GB 消费级显卡上跑得起来的四旋翼仿真器。通用引擎（PhysX / Warp / Unity）在三堵墙面前各让一步：吞吐靠 GPU、可微性直接放弃、显存交给引擎黑箱。DiffAero 的选择是三堵墙一起硬扛，代价是放弃通用性——这正是它所有设计取舍的根源。

5.2 五个具体困难：为什么难 / 怎么绕过 / 代价是什么

困难 1：CPU–GPU 往返与内核启动开销，把小算子变成瓶颈

为什么难：一个"看起来在 GPU 上"的仿真器，实际执行流常是"GPU 算一步 → 拷回 CPU → Python 里做判断/重置 → 再拷回 GPU"。一次 PCIe 往返约 $10\ \mu s$ 量级，一次 kernel launch 约 $3\sim10\ \mu s$；而一个点质量模型单步的计算量只有几十个浮点算子，传输与调度开销会远超计算本身。更隐蔽的是同步点：任何一次 .item()、if tensor > 0、np.array(tensor) 都会强制 device 同步，把流水线打断。Amdahl 定律在这里的表现是：

Eq.(C1) —— 串行占比对加速比的上界 $$ S(N)=\frac{1}{(1-p)+\dfrac{p}{N}}\;\xrightarrow{N\to\infty}\;\frac{1}{1-p} $$
$p$ = 可并行部分占比 |  $N$ = 并行度（这里可理解为并行环境数） |  含义：哪怕只有 $1\%$ 的时间花在"必须串行"的 CPU 逻辑上，加速比上界也只有 $100\times$——这解释了为什么 Aerial Gym 在 8,192 环境时吞吐开始饱和（Fig. 6 上排），而 DiffAero 仍近似线性增长：后者的 $1-p$ 被压到了接近 0。

论文怎么绕过：全栈 PyTorch——动力学是 @torch.jit.script 的纯函数（dynamics/pointmass.py:109-151），传感器是 @torch.jit.script 的解析内核（utils/sensor.py:23-121），重置用 torch.where 掩码而非 Python for（pointmass.py:67-74、obstacle_avoidance.py:257-323），统计量用张量滑窗（utils/runner.py:56-91）。整个 rollout 内没有一次 host 同步；甚至连"哪些环境该 reset"都是用布尔掩码张量表达的。

代价：（i）可扩展性受限于 PyTorch 算子集——想加一个"带摩擦的接触模型"或"三角网格碰撞"，要么用 PyTorch 硬写（慢且难），要么打破"零同步"的约定；（ii）torch.jit.script 对动态形状、Python 容器、递归都不友好，代码风格被迫"张量化 + 静态化"；（iii）无法复用生态：PhysX 的接触求解器、Habitat 的场景资产、Unity 的材质系统一律用不上。

困难 2：通用刚体引擎的动作语义与四旋翼错位

为什么难：Brax/Warp 这类可微引擎把动作定义为关节力矩，而四旋翼的物理输入是"四个电机的转速平方"。从"力矩"到"推力"中间必须有一层混控（mixer）与姿控环；若这层放在引擎外，它要么不可微（用 NumPy/PID 写），要么又是一次跨语言边界。更麻烦的是：四旋翼是欠驱动系统（4 个输入、6 个自由度），"力矩"作为动作会让策略学到大量物理上不可实现的组合。

论文怎么绕过：自研 QuadrotorModel（13 维状态：位置 3 + 四元数 4 + 速度 3 + 角速度 3），动作定义为归一化推力 + 三轴机体角速率（4 维），并把 RateController 直接写进计算图：$\boldsymbol{\tau}=J\,K_\omega(\boldsymbol{\omega}_d-\boldsymbol{\omega})+\boldsymbol{\omega}\times J\boldsymbol{\omega}$，$T=u_0\cdot\text{thrust\_ratio}\cdot g\cdot m$（dynamics/controller.py:82-103）。这样"策略输出 → 力矩 → 角加速度"整条链都在图里，梯度可以一路回传到策略。

代价：（i）只支持多旋翼——论文说"可轻易推广到六旋翼/八旋翼"，但固定翼、扑翼、地面车辆都不在范围内；（ii）丢掉了真实电机动力学——电机的一阶滞后、桨叶效率随来流变化、电池电压跌落都没有建模，靠 pmc.yaml 里的 lmbda（加速度一阶迟滞）近似；（iii）RateController 的增益 $K_\omega$ 固定为 $[1,1,1]$，是一个"理想化的内环"，与真实 PX4 的串级 PID 仍有差距。

困难 3：可微物理的"图爆炸"与梯度病态

为什么难：设 rollout 长 $T=32$、并行 $N=1024$、每步激活 $m$ 个浮点数，则 BPTT 需要保存 $\mathcal{O}(T\cdot N\cdot m)$ 的中间量；一旦 $T$ 上到几百步，显存直接爆掉。更致命的是梯度幅值：四旋翼动力学里有大量乘积与旋转，$\partial\mathbf{s}_{t+1}/\partial\mathbf{s}_t$ 的谱半径常常 $>1$，连乘 $T$ 次就是指数爆炸（梯度爆炸）；而阻尼、速度跟踪项又会让它 $<1$，连乘后指数消失（梯度消失）。这就是"物理系统的长期信用分配问题"。

Eq.(C2) —— BPTT 梯度的连乘结构（也是它脆弱的根源） $$ \frac{\partial \mathcal{L}}{\partial \mathbf{a}_{t_1}}=\sum_{t_2>t_1}\frac{\partial \ell_{t_2}}{\partial \mathbf{s}_{t_2}}\left(\prod_{t=t_1+1}^{t_2-1}\frac{\partial \mathbf{s}_{t+1}}{\partial \mathbf{s}_{t}}\right)\frac{\partial \mathbf{s}_{t_1+1}}{\partial \mathbf{a}_{t_1}} $$
与论文 Eq.(5) 同构，只是把"单条链"写成"对所有后续时刻求和"的完整形式。 |  括号里的连乘是全部问题的来源：若 $\|\partial\mathbf{s}_{t+1}/\partial\mathbf{s}_t\|_2\approx1.2$，则 30 步后放大 $1.2^{30}\approx237\times$；若约为 $0.8$，则衰减到 $0.8^{30}\approx1.2\times10^{-3}$。 |  DiffAero 的对策不是截断（truncated BPTT），而是"软化截断"——见 7.1 的 GradientDecay。

论文怎么绕过：三招组合。（i）保真度阶梯——真正用于可微学习的是 point-mass 模型（9 维状态、无姿态、无角速度），把最"陡"的姿态动力学整个拿掉；（ii）梯度衰减——GradientDecay 在反传时每步乘 $e^{-\alpha\Delta t}$（base_dynamics.py:181-192，alpha: 1.0），把"无限记忆"变成"指数遗忘"；（iii）rollout 级 detach——TrainRunner.run() 每轮开始 self.env.detach()（utils/runner.py:130），把 $1000$ 轮更新切成 $1000$ 段互不相连的短图。

代价：梯度衰减引入了偏差——它等价于"只相信最近约 $1/(\alpha\Delta t)\approx30$ 步的信用"，长于这个窗口的因果关系被系统性低估。对"避障"这类局部反应型任务无伤大雅，但对"竞速"这类需要全局规划的长期任务就是硬伤：论文 §IV-B 明确承认在 racing 上"未能设计出有效的可微奖励"，所有可微算法表现都很差。

困难 4：低分辨率视觉 vs 光栅化的固定开销

为什么难：光栅化的成本主要由像素数 × 三角形数决定，且有一条与分辨率无关的固定管线开销（顶点处理、光栅化设置、深度测试）。当图像只有 $16\times9=144$ 或 $64\times64=4096$ 像素时，这条固定开销占据主导——"花 90% 的时间准备画布，只画了 144 个点"。反过来，光线投射的成本是光线数 × 求交测试数，在"少量基元 + 低分辨率"的区域恰好更便宜：

Eq.(C3) —— 光线投射 vs 光栅化的成本量级 $$ C_{\text{ray}}\approx \underbrace{H\,W}_{\text{光线数}}\cdot\underbrace{M_{\text{eff}}}_{\text{剔除后基元数}}\cdot c_{\text{hit}}, \qquad C_{\text{raster}}\approx \underbrace{H\,W}_{\text{像素}}\cdot\underbrace{F_{\text{覆盖}}}_{\text{覆盖该像素的三角形}}\cdot c_{\text{frag}}+C_{\text{fixed}} $$
$M_{\text{eff}}$ = 经过视场/距离剔除后真正参与求交的基元数（论文 Fig. 3 的核心） |  $c_{\text{hit}}$ = 单次解析求交的代价（球：一次开方；立方体：三次除法的 slab 测试；地面：一次除法） |  $C_{\text{fixed}}$ = 光栅化管线的固定开销，与分辨率无关——这正是低分辨率下光栅化"不划算"的原因。 |  数值感受：$64\times64$ 深度图、30 个基元时 $C_{\text{ray}}\sim4096\times30\approx1.2\times10^{5}$ 次求交；而一张 $64\times64$ 的画面若场景有 $10^{4}$ 个三角形，光栅化要处理 $4096\times10^{4}$ 量级的片元测试。

论文怎么绕过：（i）按基元类型特化内核——不为三角网格写通用求交，而是为球（raydist3d_sphere）、轴对齐/带旋转的立方体（raydist3d_cube 的 slab 法）、地面平面（raydist3d_ground_plane）各写一个 @torch.jit.script 函数；（ii）剔除——只对"最近距离 $<$ max_dist"的障碍物投射光线，用 torch.where 得到 (env_id, obstacle_id) 索引对后做散射/聚集（sensor.py:236-239），把 $O(N_{\text{env}}\cdot N_{\text{obs}}\cdot N_{\text{ray}})$ 的三维张量压成 $O(M\cdot N_{\text{ray}})$，其中 $M\ll N_{\text{env}}N_{\text{obs}}$；（iii）可微——整个求交是解析式，深度图对位姿的导数天然存在。

代价：（i）场景表达能力被锁死在基元上——没有三角网格、没有纹理、没有光照，无法做"真实感视觉"研究；（ii）只适合低分辨率——论文直言 ray casting 的优势区间是"分辨率低于 $64\times64$"，一旦要 $256\times256$ 的 RGB，光栅化/NeRF 类方案会更优；（iii）遮挡关系靠 min 实现——torch.concat([...]).min(dim=1) 取最近距离，这在语义上正确，但 min 的梯度只流向最近的那一个基元，多基元"同时逼近"时梯度会跳变（非光滑）。

困难 5：可微奖励设计的"局部最优陷阱"与稀疏目标

为什么难：可微学习把"策略改进"变成了"沿 $\partial\ell/\partial\mathbf{a}$ 下降"，本质上是在势场里做梯度下降。这与经典的人工势场法（APF）同构，因而继承了它的全部病灶：局部极小（被障碍物"夹住"而停滞）、狭窄通道振荡、以及"目标不可微就无法表达"。更麻烦的是，可微奖励要求"每一步都有导数"，而"成功/失败""是否穿门"这类目标天然是离散的、导数几乎处处为 0。

论文怎么绕过：把奖励拆成两半——$R_{\text{ctrl}}$（稠密、可微、管短期行为）走一阶梯度；$R_{\text{goal}}$（稀疏、不可微、管长期目标）交给一个 critic 估计其价值 $V_\phi$，再作为终端自举项进入 actor 损失（论文 Eq. 6）。这样"不可微"的部分被 Bellman 方程"吸收"进了值函数，而不是被丢弃。

代价：（i）需要额外训练一个 critic，且 critic 的输入必须是全状态（非对称），否则 $V_\phi$ 估计不准；（ii）$R_{\text{ctrl}}$ 与 $R_{\text{goal}}$ 的权重需要人工拆两套（loss_weights 与 reward_weights），调参空间变大；（iii）当 $R_{\text{goal}}$ 本身设计得不好（如竞速），这套机制也救不回来——论文在 racing 上的失败就是证据。

6. 方法与关键公式

本节按"动力学 → 梯度 → 算法"三层展开。前两层是框架提供的"物理与导数"，第三层是建立在其上的学习算法（BPTT / SHAC / SHA2C / PPO）。所有公式均对应论文 Eq.(1)–(6)，并标注代码中的实现位置与实现与论文的差异。

6.1 四种可微动力学：一条"保真度—可学性"的滑轨

Eq.(1) —— 全四旋翼动力学（最高保真） $$ \begin{cases} \dot{\mathbf{p}}=\mathbf{v}\\[2pt] \dot{\mathbf{v}}=\mathbf{g}-c\,\mathbf{z}_B-RDR^{\top}\mathbf{v}\\[2pt] \dot{\mathbf{q}}=\tfrac12\,\mathbf{q}\odot\begin{bmatrix}0\\ \boldsymbol{\omega}\end{bmatrix}\\[2pt] \dot{\boldsymbol{\omega}}=J^{-1}\big(\boldsymbol{\tau}-\boldsymbol{\omega}\times J\boldsymbol{\omega}\big) \end{cases} $$
$\mathbf{p},\mathbf{v}$ = 世界系位置/速度 | $\mathbf{q},\boldsymbol{\omega}$ = 机体系姿态四元数/角速度 |  $\mathbf{z}_B$ = 机体 z 轴单位向量（推力方向） | $R,D,J$ = 旋转矩阵、阻尼矩阵、惯量矩阵 |  $c,\boldsymbol{\tau}$ = 总推力与总力矩 | $\odot$ = 四元数乘法。
为什么这样建模：$\mathbf{z}_B$ 把"推力永远沿机体 z 轴"这一物理事实写进方程，于是姿态决定推力方向——这是四旋翼欠驱动性的数学表达。代码见 dynamics/quadrotor.py:111-142，状态 13 维 [p(3), q(4), v(3), ω(3)]，动作 4 维（归一化推力 + 三轴角速率），RateController 负责把角速率指令转成 $\boldsymbol{\tau}$。
Eq.(2) —— 简化四旋翼动力学（保留姿态，去掉角速率环） $$ \dot{\mathbf{p}}=\mathbf{v},\qquad \dot{\mathbf{v}}=R\,\mathbf{c}+\mathbf{g},\qquad \dot{R}=R\,[\boldsymbol{\omega}]_\times $$
$[\cdot]_\times$ = 反对称矩阵算子 |  $\mathbf{c}$ = 机体系集合推力向量 |  关键简化：动作直接是"机体角速率 + 集合推力"，绕过了 Eq.(1) 里的 $\dot{\boldsymbol{\omega}}=J^{-1}(\tau-\omega\times J\omega)$——即假设内环角速率控制器是理想的（瞬时响应）。这样既保留了姿态动力学（可以研究"倾斜—加速"的耦合），又消除了最"刚"的一阶旋转动力学。
⚠ 代码现状：论文把它算作 4 个模型之一，但仓库里该模型尚未实现——cfg/dynamics/ 只有 pmc.yaml / pmd.yaml / quad.yaml，README 的 TODO-List 第一条即"Add simplified quadrotor dynamics model"。这是一个论文声明与代码实现不一致的点，复现时需注意（详见 9.1）。
Eq.(3) —— 连续时间质点动力学（可微学习的主力） $$ \dot{\mathbf{p}}=\mathbf{v},\qquad \dot{\mathbf{v}}=\mathbf{a}+\mathbf{g}-d\,\mathbf{v},\qquad \dot{\mathbf{a}}=\lambda\,(\mathbf{u}-\mathbf{a}) $$
$\mathbf{a}$ = 世界系实际加速度（作为状态的一部分被积分） |  $\mathbf{u}$ = 策略给出的期望加速度指令 |  $d$ = 归一化阻尼系数（默认 $0.375$，随机化区间 $[0.3,0.45]$） |  $\lambda$ = 控制迟滞因子（默认 $2.6$，随机化区间 $[2.5,2.7]$）。
为什么是"一阶迟滞"而不是"瞬时响应"：$\dot{\mathbf{a}}=\lambda(\mathbf{u}-\mathbf{a})$ 是一个一阶低通，其时间常数 $\tau=1/\lambda\approx0.38$ s。它用一个参数概括了"电机 + 桨叶 + 内环姿态控制器"的全部延迟——这是本框架最重要的建模取舍：既保留了真实系统最关键的相位滞后（决定策略能否稳定），又让梯度保持平滑（没有开关、没有饱和）。
代码实现（dynamics/pointmass.py:109-151）把它写成离散形式：$\mathbf{a}_{t+1}=\text{lerp}(\mathbf{a}_t,\mathbf{u}_t,1-e^{-\lambda\Delta t})$，其中 control_delay_factor = (1 - exp(-λ·dt))/dt 用于连续形式的 $\dot{\mathbf{a}}$。注意：代码里还额外把阻力项 $-D\mathbf{v}$ 并入 $\mathbf{a}$ 的更新（next_a = lerp(...) - D*v），与论文公式的写法略有出入，但物理等价于"加速度状态吸收了阻力"。
Eq.(4) —— 离散时间质点动力学（最快、最平滑） $$ \mathbf{p}_{t+1}=\mathbf{p}_t+\mathbf{v}_t\Delta t+\tfrac12\,\mathbf{u}_t\Delta t^{2},\qquad \mathbf{v}_{t+1}=\mathbf{v}_t+\tfrac12\,(\mathbf{u}_t+\mathbf{u}_{t+1})\Delta t $$
$\mathbf{u}_t$ = 第 $t$ 步的加速度指令（直接作为控制量，没有迟滞状态） |  $\tfrac12(\mathbf{u}_t+\mathbf{u}_{t+1})$ = 梯形积分，用"当前与下一步指令的平均"来近似区间平均加速度。
为什么它"最适合可微"：状态只有 6 维（位置 + 速度），$\partial\mathbf{p}_{t+1}/\partial\mathbf{u}_t=\tfrac12\Delta t^{2}I$ 是一个常数矩阵——梯度不随状态变化、不会爆炸也不会消失。代价是完全没有姿态，只能做"质点式"的路径规划。
⚠ 步进与实现的差异：代码 discrete_point_mass_dynamics_local/world（pointmass.py:182-222）在这两条式子基础上额外加了阻力与迟滞：next_a = lerp(a_thrust, cmd, 1-exp(-λdt)) - D*v、next_v = v + dt*(0.5*(a_thrust+next_a) + G)。也就是说，仓库里的 pmd 比论文 Eq.(4) 更"物理"一些，但仍然只有 9 维状态、没有姿态。
模型状态维度动作维度保留了什么适用场景 / 论文结论
quad134姿态、角速度、推力方向耦合、气动阻尼需要精确姿态动力学时使用；Fig. 8 显示收敛最慢、训练开销最大，但保真度最高
simple——姿态（无角速度环）论文列出但代码未实现（README TODO）
pmc93质心运动 + 加速度迟滞 + 阻力论文实验的主力：SHA2C 实飞策略即用此模型训练；梯度平滑、收敛快
pmd93质心运动（梯形积分）最省算力，适合"极限速度"场景；论文称其为"prioritizing extreme simulation speed"
🔍 姿态从哪来？—— point_mass_quat() 的三步反解
点质量模型没有姿态状态，但仿真器仍需输出一个"看起来合理"的姿态（供渲染、供 IMU、供部署时给 PX4 姿态指令）。代码用一个纯几何构造解决（dynamics/pointmass.py:238-280）：
① 定 z 轴：机体 z 轴 = 归一化的推力加速度方向 $\hat{\mathbf{a}}$（因为螺旋桨推力沿机体 z 轴）；
② 定偏航：偏航角取"速度指数滑动平均（EMA）在水平面的投影"的方向 $\psi=\operatorname{atan2}(\bar v_y,\bar v_x)$——即"机头朝向飞行方向"，不侧滑；
③ 合成：先在偏航系里求出"把 $\mathbf{z}$ 转到 $\hat{\mathbf{a}}$ 的最小旋转"（轴角 → 四元数），再左乘偏航四元数，得到最终姿态。
这段计算被显式放在 torch.no_grad() 里——姿态不参与梯度。这是一个非常重要的工程决定：姿态是"渲染与部署的装饰品"，不是"优化的变量"。论文 §III-B 也承认其副作用：在高度杂乱的室内环境中，"原地转向以观察"这种机动无法被表达。

6.2 梯度如何穿过动力学：BPTT（论文 Eq.5）

Eq.(5) —— 状态对历史动作的雅可比链 $$ \frac{\partial \mathbf{s}_{t_2}}{\partial \mathbf{a}_{t_1}} =\frac{\partial \mathbf{s}_{t_1+1}}{\partial \mathbf{a}_{t_1}} \prod_{t=t_1+1}^{t_2-1}\frac{\partial \mathbf{s}_{t+1}}{\partial \mathbf{s}_{t}}, \qquad t_2>t_1 $$
$\partial\mathbf{s}_{t+1}/\partial\mathbf{s}_t$ = 单步状态转移雅可比（由 RK4/Euler 的复合函数自动微分得到） |  $\partial\mathbf{s}_{t_1+1}/\partial\mathbf{a}_{t_1}$ = 控制输入的直接灵敏度。
实践含义：这个式子说明"$\mathbf{a}_{t_1}$ 对 $\ell_{t_2}$ 的影响"是一串矩阵乘积。它既是可微学习的全部力量来源（无需采样即可得到策略梯度），也是它脆弱的根源（连乘导致爆炸/消失，见 Eq.(C2)）。框架层面：只要 dynamics.step() 不被 detach()，PyTorch 就会自动构建这条链——DiffAero 的全部"可微"能力，本质上就是"不 detach"这一个约定的产物。

APG（algo/APG.py）是这条式子最朴素的实现：跑 $T$ 步 rollout，把每步的 loss 累加，最后一次 backward()。三个实现细节决定它能否工作：

Eq.(M1) —— APG / BPTT 的 actor 损失（含熵正则） $$ \mathcal{L}_{\text{APG}}(\theta)=\frac{1}{T}\sum_{t=0}^{T-1}\ell_t \;-\;\beta\,\frac{1}{T}\sum_{t=0}^{T-1}\mathcal{H}\big[\pi_\theta(\cdot\mid \mathbf{o}_t)\big] $$
$\ell_t$ = 环境的可微惩罚（注意：损失越小越好，所以这里不带负号） |  $\mathcal{H}$ = 高斯策略的微分熵 |  $\beta$ = entropy_weight（apg_sto.yaml 中为 $0.03$）——减去熵即"鼓励探索"。
代码细节：APG.record_loss() 先对 batch 取 loss.mean() 再累加，最后除以 l_rollout（APG.py:36-51）；梯度裁剪阈值 max_grad_norm: 1.。确定性变体 apg 没有熵项，直接对 DeterministicActor 反传。
⚠ 两个论文没写、但复现必须知道的"魔改系数"
① loss/10：在 SHAC.step() 中，写入 buffer 的损失是 loss/10，源码注释直白地写着 "divide by 10 to avoid instability"（algo/SHAC.py:182-191）。这是一个纯经验性的量纲缩放——因为可微损失的绝对幅值（例如避障项 $w_{\text{oa}}=5$ × 归一化速度）会让 actor 梯度过大。
② actor_loss / (N·T)：update_actor() 用 self.actor_loss / (self.n_envs * self.l_rollout) 归一化（SHAC.py:135），于是学习率对 n_envs 与 l_rollout 的敏感度被部分消除——但并不完全：当 n_envs 从 1024 变到 4096 时，梯度噪声下降而步长不变，实际等效学习率会变化。这类"隐式超参"是复现可微 RL 论文时最常见的坑。

6.3 SHAC：用 critic 吸收"不可微"的部分

SHAC（Short-Horizon Actor-Critic）的核心是把"无限视界的最优控制"截断成"短视界内的可微奖励 + 视界末端的价值自举"。DiffAero 的实现（algo/SHAC.py:21-242）用 V 型 critic（而非 Q），actor 损失为：

Eq.(M2) —— SHAC 的 actor 损失 $$ \mathcal{L}_{\text{SHAC}}(\theta)=-\frac{1}{NT}\sum_{i=1}^{N}\Bigg[\sum_{t=0}^{T-1}\gamma^{t}\,\ell\big(\mathbf{s}^{i}_{t},\mathbf{a}^{i}_{t}\big)\;+\;\gamma^{T}V_{\phi}\big(\mathbf{s}^{i}_{T}\big)\Bigg] $$
与论文 Eq.(6) 完全同构，只是把 $R_{\text{ctrl}}$ 写成通用的 $\ell$。 |  $\gamma^{T}V_\phi(\mathbf{s}_T)$ = 视界末端的状态价值——它把"$T$ 步之后发生的一切"压缩成一个标量，从而让可微视界只需覆盖 $T=32$ 步（sha2c.yaml: l_rollout: 32），大幅降低显存与梯度病态。 |  $\ell$ 的符号：代码里 loss 本身是"惩罚"，故 actor 损失里是 $+\ell$、而终端价值是 $-\gamma^TV$（SHAC.py:300 写作 cumulated_loss - terminal_value）——最小化损失 ⇔ 最大化价值。
critic 目标：用 TD-λ 对同一批 $\ell$ 做自举，bootstrap_tdlambda() 用递推的 $A_i,B_i,\lambda_i$ 三个累加器实现"带终止掩码的 λ-return"（SHAC.py:70-91）；若 lmbda=0 则退化为单步 TD。critic 用 MSE 损失、n_minibatch: 8 个小批量、目标网络以 target_update_rate: 1.0（即硬更新）同步。
💡 为什么"短视界 + 终端价值"能同时解决显存与稀疏奖励两个问题
若不用 critic（纯 BPTT），要覆盖"从起飞到到达目标"的完整因果链，$T$ 必须达到数百步，显存与梯度病态都不可接受；若用 critic 但只做零阶（纯 RL），则完全放弃了可微梯度，样本效率退回 PPO 水平。SHAC 的折中是：让"能被微分的那部分因果"（短期、稠密、连续）走一阶梯度，让"不能被微分的那部分"（长期、稀疏、离散）走零阶价值估计。这实际上是把 Bellman 方程当作"梯度的压缩器"——用一次函数逼近，替代了 $T$ 步的链式求导。理解这一点，就理解了整个可微 RL 领域的核心 trade-off。

6.4 SHA2C：本文提出的混合算法（论文 Eq.6）

Eq.(6) —— SHA2C 的 actor 损失（原文公式） $$ L(\theta)=-\frac{1}{NT}\sum_{i=1}^{N}\Bigg[\Big(\sum_{t=0}^{T-1}\gamma^{t}R_{\text{ctrl}}\big(\mathbf{s}^{i}_{t},\mathbf{a}^{i}_{t}\big)\Big)+\gamma^{T}V_{\phi}\big(\mathbf{s}^{i}_{T}\big)\Bigg] $$
$R_{\text{ctrl}}$ = 稠密、可微的局部控制奖励（管短期行为） |  $R_{\text{goal}}$ = 稀疏、不可微的目标奖励（二值成功/失败标志，管长期行为），不直接出现在 actor 损失里，而是通过 $V_\phi$（只用 $R_{\text{goal}}$ 训练的价值网络）以终端自举的形式进入 |  $\mathbf{s}^i_T$ = 第 $i$ 条轨迹末端重置前的全状态（代码里由 extra["next_state_before_reset"] 提供，且断言 requires_grad == True） |  与 SHAC 的唯一差别：SHAC 的 $\ell$ 与 $V$ 用同一个奖励；SHA2C 把二者解耦——$\ell=R_{\text{ctrl}}$ 走一阶，$V$ 拟合 $R_{\text{goal}}$ 走零阶。

SHA2C = SHAC + 非对称 actor-critic + 双奖励解耦

【解决的问题】可微学习要求奖励"处处可微且稠密"，但真实任务的目标（"到达""通过门""不撞"）是稀疏、离散、不可微的。SHAC 虽然引入了 critic，但其 critic 仍在拟合同一套稠密奖励，等于没有解决"目标不可微"的问题。
【关键设计 1：双奖励】$R_{\text{ctrl}}$ 负责"飞得稳、不贴障碍、朝目标"（可微），$R_{\text{goal}}$ 只给"成功 +1 / 失败 −1"（不可微）。配置上体现为 loss_weights（进梯度）与 reward_weights（进 critic）两套独立的权重表。
【关键设计 2：非对称】actor 只看 $16\times9$ 深度 + 9 维标量（部署时可得）；critic 看 247 维全状态（仿真时才有）。这让 $V_\phi$ 的估计方差大幅下降，而策略本身仍可在实机上运行——这是"特权信息"（privileged information）在可微 RL 中的一次干净应用。
【代价】需要两个网络、两套权重、两次前向；且 next_state_before_reset 的获取要求环境在 reset 之前导出全状态（env/obstacle_avoidance.py:136-139），这给自定义环境增加了接口负担。

把论文的叙述与代码合起来，SHA2C 的一个更新轮次可以精确地写成下面这个流程：

  1. 采样：obs ← env.get_observations()；a ← tanh(μ_θ(o) + σ_θ(o)⊙ε)；u ← env.rescale_action(a)；state ← env.get_state()（全状态，供 critic）。
  2. 推演：env.step(u) 内部执行 dynamics.step → imu.step → terminated/truncated → 传感器更新 → loss_and_reward，返回 (loss, reward) 与 next_state_before_reset。
  3. 累加：cumulated_loss += rollout_gamma * loss；actor_loss += cumulated_loss[reset].sum() − rollout_gamma·γ·V(next_state)[truncated].sum()；rollout_gamma ← where(reset, 1, rollout_gamma·γ)（SHAC.py:288-306）。
  4. critic：用 $R_{\text{goal}}$ 的 TD-λ 目标对 $V_\phi(\mathbf{s})$ 做 MSE 回归（小批量 8 个）。
  5. actor：对 actor_loss/(N·T) + β·entropy_loss 反传——梯度会穿过 $T=32$ 步的动力学链，一直回到策略参数。
  6. 清理：agent.detach()、env.detach()，进入下一轮。

6.5 对照基线：PPO 与 DreamerV3

Eq.(M3) —— PPO 的 clipped 目标与 GAE $$ L^{\text{CLIP}}(\theta)=\mathbb{E}_{t}\Big[\min\big(\rho_t(\theta)\hat A_t,\;\operatorname{clip}(\rho_t(\theta),1-\epsilon,1+\epsilon)\hat A_t\big)\Big], \quad \rho_t=\frac{\pi_\theta(\mathbf{a}_t\mid\mathbf{o}_t)}{\pi_{\theta_{\text{old}}}(\mathbf{a}_t\mid\mathbf{o}_t)} $$ $$ \hat A_t^{\text{GAE}}=\sum_{l=0}^{T-t-1}(\gamma\lambda)^{l}\delta_{t+l},\qquad \delta_t=r_t+\gamma V_\phi(\mathbf{o}_{t+1})-V_\phi(\mathbf{o}_t) $$
$\epsilon=0.2$（ppo.yaml: clip_coef） | $\lambda=0.95$ | $\gamma=0.99$ |  训练配置：l_rollout: 16、lr: 0.0026、n_epoch: 4、n_minibatch: 8、value_weight: 2、norm_adv: True、clip_value_loss: True。
与可微算法的对照意义：PPO 的梯度不穿过动力学——$\hat A_t$ 是标量，$\nabla_\theta\log\pi_\theta$ 只依赖策略本身。因此它的样本效率由"奖励信号的稠密程度"决定，而不是由"物理模型的质量"决定。这正是 Fig. 7 中"位置控制里可微算法碾压 PPO、而竞速任务里 PPO 反超"的根本原因。

DreamerV3（algo/dreamerv3/）走的是第三条路：先学一个隐状态世界模型（world.py、state_predictor.py），再在"想象"中训练 actor-critic。它不需要环境可微，也不需要大量真实交互（论文 Fig. 7 注明 DreamerV3 "needs far more updates and fewer data than other algorithms"）。在 DiffAero 里它的价值是提供一个"数据效率上界"的参照：如果可微算法在样本效率上还不如一个世界模型，那"可微"这个卖点就不成立——Fig. 7 显示在位置控制上可微算法确实超过了 DreamerV3，这是论文最有分量的一张图（见 8.3 的解读）。

6.6 传感器模型：可微的"感知"

Eq.(M4) —— 三类基元的解析光线求交 $$ \textbf{球：}\quad t=\langle \mathbf{c}-\mathbf{o},\hat{\mathbf{d}}\rangle-\sqrt{r^{2}-\big\|\mathbf{c}-\mathbf{o}\big\|^{2}+\langle\mathbf{c}-\mathbf{o},\hat{\mathbf{d}}\rangle^{2}} $$ $$ \textbf{立方体（slab）：}\quad t_{\text{in}}=\max_{k}\min\big(t_k^{\min},t_k^{\max}\big),\quad t_{\text{out}}=\min_{k}\max\big(t_k^{\min},t_k^{\max}\big),\quad t_k^{\min/\max}=\frac{b_k^{\min/\max}-o_k}{d_k} $$ $$ \textbf{地面：}\quad t=\frac{z_g-o_z}{d_z}\quad\text{iff}\quad (o_z-z_g)\,d_z<0 $$
$\mathbf{o},\hat{\mathbf{d}}$ = 光线起点（无人机位置）与单位方向（由 $H\times W$ 像素网格 + 机体系→世界系旋转换算） |  球：判别式 $\Delta=r^2-\|\mathbf{c}-\mathbf{o}\|^2+\langle\cdot\rangle^2>0$ 且 $\langle\mathbf{c}-\mathbf{o},\hat{\mathbf{d}}\rangle>0$ 才算命中（sensor.py:24-54） |  slab 法：对三个轴分别求进入/离开参数，取"最晚进入、最早离开"，t_in ≤ t_out 且 t_out ≥ 0 才算命中；带旋转的立方体先把光线变换到立方体局部系（sensor.py:57-97） |  地面：单次除法 + 符号判定（sensor.py:100-121）。
最终深度：所有基元取 $\min$，再与地面取 $\min$，最后归一化为 $\text{depth}=1-d/d_{\max}\in[0,1]$（sensor.py:176-182）——注意它是"越近越亮"，这解释了 Fig. 10 中深度图可视化为何近处障碍物呈亮色。$d_{\max}=5$ m（相机）/ $20$ m（LiDAR）。
Eq.(M5) —— IMU 的噪声与随机游走漂移 $$ \mathbf{b}_{k+1}=\mathbf{b}_{k}+\sigma_{\text{drift}}\sqrt{\Delta t}\;\mathbf{n}_k,\qquad \tilde{\boldsymbol{\omega}}_k=\boldsymbol{\omega}_k+\mathbf{b}_k+\frac{\sigma_{\text{noise}}}{\sqrt{\Delta t}}\,\mathbf{n}'_k $$ $$ \boldsymbol{\theta}_{k+1}=\boldsymbol{\theta}_k+\big(\mathbf{b}^{\text{gyro}}_k+\boldsymbol{\eta}_k\big)\Delta t,\qquad \mathbf{p}^{\text{drift}}_{k+1}=\mathbf{p}^{\text{drift}}_k+\mathbf{v}^{\text{drift}}_k\Delta t $$
$\sigma_{\text{drift}}\sqrt{\Delta t}$ = 随机游走增量（与 $\sqrt{\Delta t}$ 成正比，符合布朗运动标度） |  $\sigma_{\text{noise}}/\sqrt{\Delta t}$ = 单样本白噪声（与 $\sqrt{\Delta t}$ 成反比，保证积分后方差与 $\Delta t$ 无关） |  安装误差：imu_mounting_error_range_deg: 2.，每回合随机旋转传感器坐标系 |  默认参数（cfg/env/imu/default_imu.yaml）：acc_drift_std≈0.1356、acc_noise_std≈0.1569、gyro_drift_std≈1.435e-3、gyro_noise_std≈2.443e-2，且 enable_drift/enable_noise 均可开关。
为什么重要：IMU 是唯一"不可微"的传感器（含随机噪声），它的存在使"基于里程计的策略"必须承受与实机同量级的漂移——这是 sim-to-real 的必要条件，也让 imu.p_w / v_w / q 这些属性成为"带漂移的真值"。

7. 核心技术原理详解

本节挑出四个"真正的技术内核"深挖：① 梯度如何穿过物理引擎并被"软化截断"；② 并行仿真的内存布局与剔除策略；③ 光线投射的几何推导与梯度非光滑性；④ 混合学习的目标分解到底"混"在哪一步。目标是读到能自己复现的程度。

7.1 原理一：梯度穿过物理引擎——GradientDecay 的数学

7.1.1 前向：一条没有断点的计算图

7.1.2 反向：一个自定义 autograd Function 的"指数遗忘"

关键代码只有 12 行（dynamics/base_dynamics.py:181-192）：

Eq.(P1) —— GradientDecay 的 forward / backward $$ \text{forward}:\quad \mathbf{s}_{t+1}\mapsto \mathbf{s}_{t+1}\ \text{（恒等）};\qquad \text{saved}:\quad \kappa=e^{-\alpha\Delta t} $$ $$ \text{backward}:\quad \frac{\partial \mathcal{L}}{\partial \mathbf{s}_{t+1}}\;\longmapsto\;\kappa\cdot\frac{\partial \mathcal{L}}{\partial \mathbf{s}_{t+1}} $$
$\alpha$ = alpha，默认 $1.0$（pmc / quad）、$2.0$（pmd） |  $\Delta t=0.0333$ s |  $\kappa=e^{-0.0333}\approx0.9672$。
它不是"梯度裁剪"，也不是"detach"：前向数值完全不变（所以仿真结果、奖励、曲线与不加这个函数时一模一样），只有反向的幅值被乘上一个 $<1$ 的常数。这保证了"物理仍然精确，只有信用分配被软化"——这是它比 truncated BPTT 优雅的地方。

7.1.3 等价推导：把它展开会看到什么

设第 $t$ 步的损失为 $\ell_t$，未加衰减时 $\mathbf{a}_{t_1}$ 收到的梯度是 Eq.(5) 的连乘。加入 GradientDecay 后，每穿过一个状态节点就多乘一个 $\kappa$。于是：

Eq.(P2) —— 有效信用分配权重与"记忆地平线" $$ \frac{\partial \mathcal{L}}{\partial \mathbf{a}_{t_1}} =\sum_{\Delta=1}^{T-t_1}\kappa^{\Delta}\, \frac{\partial \ell_{t_1+\Delta}}{\partial \mathbf{s}_{t_1+\Delta}} \Bigg(\prod_{t=t_1+1}^{t_1+\Delta-1}\frac{\partial \mathbf{s}_{t+1}}{\partial \mathbf{s}_{t}}\Bigg) \frac{\partial \mathbf{s}_{t_1+1}}{\partial \mathbf{a}_{t_1}}, \qquad \kappa=e^{-\alpha\Delta t} $$ $$ H_{\text{eff}}\;\approx\;\frac{1}{\alpha\,\Delta t}\;=\;\frac{1}{1.0\times0.0333}\;\approx\;30\ \text{步}\;\approx\;1.0\ \text{s} $$
$\kappa^{\Delta}$ = 相隔 $\Delta$ 步的"信用折扣"——与 RL 里的 $\gamma^{\Delta}$ 数学形式完全相同，只不过 $\gamma$ 作用在奖励上，$\kappa$ 作用在梯度上。 |  $H_{\text{eff}}$ = 有效记忆步数：$\Delta=30$ 时 $\kappa^{30}\approx0.37$，$\Delta=70$ 时 $\approx0.10$，$\Delta=140$ 时 $\approx0.01$。也就是说，超过约 1 秒的因果链，其梯度贡献基本被抹平。 |  与截断的对比：truncated BPTT 在 $T$ 处硬切，估计量有偏但方差低；GradientDecay 是软切，偏差随 $\Delta$ 平滑增长、方差同样被压低，且不会出现"第 32 步有效、第 33 步完全无效"的突变。
🎯 "可微视界 ≈ 1 秒"——一个能解释很多实验现象的推论
$T=32$ 步 × $\Delta t=0.0333$ s $=1.07$ s，而 $H_{\text{eff}}\approx1.0$ s，两者几乎重合。这不是巧合，而是设计：l_rollout=32 与 alpha=1.0 被调成"硬截断"与"软遗忘"在同一时间尺度上。由此可以推断：
① 位置控制为什么可微算法碾压 PPO：任务是"1 秒内该往哪加速"，完全落在可微视界内，一阶梯度信息量最大；
② 竞速为什么可微算法全崩：穿越 8 个门需要数秒到十几秒的全局规划，远超 1 秒视界，梯度只能看到"眼前这一小段"，等价于贪心——必然掉进局部最优；
③ 避障为什么 SHA2C 最好：避障本质是"局部反应型"（看到障碍 → 侧向让开），恰好落在视界内；而"最终要到达目标"这个长期约束由 critic 的终端价值兜底。三者合起来，Fig. 7 的三列结果几乎可以被这一个数字预测。

7.1.4 一个必须指出的实现事实：观测被 detach 了

⚠ "可微渲染"是能力，不是当前训练的用法
尽管传感器内核（球/立方体/地面求交）全部由可微算子构成，但在发布的训练循环里：get_observations() 默认 with_grad=False 并整体 .detach()（env/obstacle_avoidance.py:77-98），深度图经 sensor_tensor.copy_() 写入缓冲区（copy_ 会切断梯度）。因此论文实验中的梯度实际来自"状态/奖励"通路，而不是"像素"通路。真正被"可微感知"赋能的是未来的算法（例如直接用深度图的函数做损失、或做可微的视觉伺服），而不是本论文已跑通的实验。论文在 Related Work 中引用 [14] 讨论"直接优化视觉特征"时，用的是"enables"这类措辞，读时应理解为能力声明而非实验结论。

7.2 原理二：并行仿真的内存布局与"剔除"

7.2.1 统一的内存布局：[n_envs, n_agents, ...]

DiffAero 的所有状态张量都以 n_envs 为第 0 维、n_agents 为第 1 维（单机时用 squeeze_(1) 去掉该维，见 pointmass.py:28-33）。这个看似平凡的选择带来三个直接后果：

  • 没有 Python 循环：所有环境在同一次 kernel launch 中推进，避免了"每环境一次 launch"的 $N$ 倍调度开销（对应 5.2 的困难 1）。
  • reset 用掩码而非分支：torch.where(mask, new_state, old_state)（obstacle_avoidance.py:277），部分环境重置不会打断整批的流水线。
  • 统计量也在 GPU 上滑窗：RecordEpisodeStatistics 用 torch.roll 维护长度 $N$ 的环形缓冲（runner.py:79-90），只在写 TensorBoard 时才 .item() 一次——同步点被压到"每 log_freq 次"。

7.2.2 剔除：把三维张量压成一维索引对

Eq.(P3) —— 剔除前后的中间张量规模 $$ \underbrace{N_{\text{env}}\cdot N_{\text{obs}}\cdot N_{\text{ray}}}_{\text{朴素：全对全}} \;\longrightarrow\; \underbrace{M\cdot N_{\text{ray}}}_{\text{剔除后}},\qquad M=\big|\{(i,j):d_{ij}\le d_{\max}\}\big| $$
按仓库默认值（$N_{\text{env}}=1024$、$N_{\text{obs}}=30$、$N_{\text{ray}}=16\times9=144$）估算：朴素做法单个中间张量为 $1024\times30\times144=4.42\times10^{6}$ 个浮点（约 17.7 MB），而光线求交内部至少需要 6–10 个同形状中间量，单步就可达 100–180 MB；若再进入 BPTT（32 步），显存将直接失控。
剔除后只有"最近距离 $\le d_{\max}=5$ m"的 $(i,j)$ 对参与计算。在 $50\times50$ m 场地、30 个障碍物的设置下，$M$ 通常只有 $N_{\text{env}}$ 的 2–5 倍（数量级约 $10^{3}$），中间张量降到 MB 级——这就是"$1.8\times$ 物理、$9.6\times$ 深度"这两个数字背后最实在的工程来源。
代码位置：utils/sensor.py:236-239 用 torch.where(dist2obstacles.le(self.max_dist)) 得到 env_ids, obstacle_ids，再按"球在前、立方体在后"拆成两组索引；get_ray_dist() 用这些索引收集光线起点/方向，算完再散射回 [N_env, N_obs, N_ray] 的空壳里（初始值填 max_dist），最后 min 聚合。
💡 这个"散射—聚集"模式是 GPU 仿真的通用范式
它把"稠密但绝大多数无效"的计算（30 个障碍物里只有 3 个在 5 m 内）转化为"稀疏但全部有效"的计算。代价是：（i）索引张量的构造本身有开销（一次 argsort/where + 一次 gather）；（ii）批量大小 $M$ 随环境状态动态变化，导致每次 kernel 的并行度不同，GPU 利用率抖动；（iii）索引相关的算子（gather/scatter）的梯度实现比稠密算子更贵。这三点在"障碍物极密集"或"障碍物极稀疏"两种极端场景下都会让剔除的收益下降——论文没有给出这两端的消融。

7.2.3 显存账：为什么默认值是 1024 环境 × 32 步

粗算一次 rollout 的主要显存项（float32）：

  • 状态与动作：$1024\times(9+3)\times4\ \text{B}\approx49$ KB/步——可忽略。
  • 深度缓冲：$1024\times144\times4\ \text{B}\approx590$ KB/步——可忽略。
  • BPTT 中间激活：假设每步保留约 30 个 $[1024,9]$ 量级的中间张量，约 $1.1$ MB/步；32 步约 35 MB——对 24 GB 显卡微不足道。
  • 真正的显存大头不是仿真，而是网络与优化器：RCNN 的 512 维隐状态、8 个小批量的前向缓存、Adam 的一阶/二阶动量（参数量 ×3）。论文 Fig. 6 下排之所以要把"物理"与"深度渲染"分开测，正是因为渲染的显存随环境数线性增长，而物理的显存几乎与环境数无关。

7.3 原理三：光线投射的几何，以及 min 带来的非光滑

7.3.1 球：从二次方程到代码里的三角形式

设光线 $\mathbf{o}+t\hat{\mathbf{d}}$（$\|\hat{\mathbf{d}}\|=1$），球心 $\mathbf{c}$、半径 $r$。交点满足 $\|\mathbf{o}+t\hat{\mathbf{d}}-\mathbf{c}\|^2=r^2$，展开得一元二次方程：

Eq.(P4) —— 球求交的两种等价写法 $$ t^{2}-2t\langle\mathbf{c}-\mathbf{o},\hat{\mathbf{d}}\rangle+\big(\|\mathbf{c}-\mathbf{o}\|^{2}-r^{2}\big)=0 \;\Longrightarrow\; t=\langle\mathbf{c}-\mathbf{o},\hat{\mathbf{d}}\rangle\pm\sqrt{r^{2}-d_{\perp}^{2}} $$ $$ d_{\perp}=\|\mathbf{c}-\mathbf{o}\|\sin\theta,\qquad \cos\theta=\frac{\langle\mathbf{c}-\mathbf{o},\hat{\mathbf{d}}\rangle}{\|\mathbf{c}-\mathbf{o}\|} $$
$d_\perp$ = 球心到光线的垂距 |  代码取"减号"分支（近端交点），且要求 $d_\perp<r$ 且 $\cos\theta>0$（球在光线前方），否则返回 max_dist（sensor.py:45-54）。
一个数值细节：sintheta = torch.where(costheta>0, sqrt(1-costheta²), 0.9)——当 $\cos\theta\le0$（球在背后）时，直接给 $0.9$ 而非 $0$，既避免了 $\sqrt{1-\cos^2\theta}$ 在 $\cos\theta\approx-1$ 附近的开方病态，又保证"背后"的球一定被判为无效（$d_\perp=0.9\|\mathbf{c}-\mathbf{o}\|$ 通常 $>r$）。这类"用一个假的常数把分支焊死"的技巧，是可微/可 jit.script 代码的典型写法。

7.3.2 立方体：slab 法与旋转处理

轴对齐盒子的求交可以逐轴进行：对第 $k$ 轴，光线在 $t_k^{\min}=(b_k^{\min}-o_k)/d_k$ 进入、在 $t_k^{\max}=(b_k^{\max}-o_k)/d_k$ 离开（若 $d_k<0$ 则交换）。三轴取交：$t_{\text{in}}=\max_k\min(t_k^{\min},t_k^{\max})$，$t_{\text{out}}=\min_k\max(t_k^{\min},t_k^{\max})$，命中条件 $t_{\text{in}}\le t_{\text{out}}$ 且 $t_{\text{out}}\ge0$。带旋转的立方体则先把光线变换到立方体局部系（rotmat @ (start - p_cube)），再做 slab 测试（sensor.py:80-88）——因为旋转光线比旋转盒子便宜。

7.3.3 非光滑性：min/max 只把梯度给"赢家"

⚠ 这是"可微仿真"最容易被忽视的数学缺陷
深度图的聚合是 $\text{depth}=\min_j d_j$，避障惩罚是 $\ell_{\text{oa}}=\max_i(\cdot)$。这两个算子的次梯度只流向取到极值的那个基元：当两架障碍物几乎等距时，$\partial\text{depth}/\partial\mathbf{p}$ 会发生跳变；当最危险障碍物在帧间切换时，$\partial\ell_{\text{oa}}/\partial\mathbf{p}$ 会突变。其后果是：梯度场在"两个障碍物之间"的区域不连续，策略在这种狭窄通道里容易出现抖动或停滞（与势场法的经典病灶同源）。
论文的缓解手段：$\kappa_i=e^{-d_i^{\text{inf}}}$ 是一个光滑的"危险度"权重，使得"换一个最危险障碍物"时两侧的权重接近（若距离接近则 $\kappa$ 接近），从而把跳变幅度压小；但没有消除非光滑性。真正彻底的做法是 soft-min（$\text{softmin}_\beta(x)=-\frac1\beta\log\sum e^{-\beta x_i}$），代价是引入一个需要调的 $\beta$——论文未采用，这也是一个可做的改进点（见 9.2）。

7.4 原理四：混合学习"混"在哪一步——一阶与零阶的精确分界

论文说"SHA2C optimizes $R_{\text{ctrl}}$ and $R_{\text{goal}}$ with first- and zeroth-order policy gradient, respectively"。这句话容易被误读成"$R_{\text{goal}}$ 那部分不产生对 actor 的梯度"。严格地看代码，事实更精细：

Eq.(P5) —— 把 Eq.(6) 对 $\theta$ 求导后看到的两项 $$ \nabla_\theta L =-\frac{1}{NT}\sum_{i}\Bigg[ \underbrace{\sum_{t}\gamma^{t}\,\nabla_\theta R_{\text{ctrl}}\big(\mathbf{s}^{i}_{t},\mathbf{a}^{i}_{t}\big)}_{\text{① 一阶：穿过动力学}} \;+\;\underbrace{\gamma^{T}\,\nabla_{\mathbf{s}}V_{\phi}\big(\mathbf{s}^{i}_{T}\big)^{\top}\,\frac{\partial \mathbf{s}^{i}_{T}}{\partial \theta}}_{\text{② 仍然是穿过动力学的一阶项}} \Bigg] $$
① = 稠密奖励对参数的直接导数，路径是 $\theta\to\mathbf{a}\to\mathbf{s}\to R_{\text{ctrl}}$。 |  ② = 终端价值项。注意它也含 $\partial\mathbf{s}_T/\partial\theta$——也就是说，$V_\phi$ 对 actor 而言扮演的是"学出来的终端代价"（learned terminal cost），它的梯度依然是一阶地穿过动力学的。
那"零阶"在哪里？在 $V_\phi$ 的训练方式上：$V_\phi$ 是用 $R_{\text{goal}}$ 的标量回报做回归（TD-λ / MSE）学出来的，这个学习过程不需要 $R_{\text{goal}}$ 可微——这才是"零阶"的确切含义。文献里常说的"用零阶方法处理不可微奖励"，指的正是"把不可微的部分交给值函数/黑箱优化"，而不是"actor 的这一步梯度是零阶的"。
信号来源如何进入 actor 更新偏差 / 方差特征
$R_{\text{ctrl}}$（稠密）物理状态的可微函数直接对 $\theta$ 求导（一阶，穿过 $T$ 步动力学）低方差、有偏（视界截断 + 梯度衰减）；偏差随 $H_{\text{eff}}$ 增大而减小
$V_\phi$（终端价值）对 $R_{\text{goal}}$ 的回归作为终端代价，仍以 $\partial\mathbf{s}_T/\partial\theta$ 进入（一阶）偏差来自函数逼近误差；方差远低于"蒙特卡洛稀疏奖励"
$R_{\text{goal}}$（稀疏）成功/失败二值标志不直接进入；只通过训练 $V_\phi$ 间接影响若直接用于策略梯度（如 PPO），则高方差——这正是 SHA2C 要绕开的东西
🎯 所以 SHA2C 的实质是"用值函数做一次梯度压缩"
Bellman 最优性方程告诉我们：$V^\pi(\mathbf{s}_T)=\mathbb{E}\big[\sum_{k\ge T}\gamma^{k-T}R_{\text{goal}}\big]$。SHA2C 把"$T$ 步之后所有不可微奖励的总和"替换成它的条件期望，于是：无限长的、不可微的信用链 → 一个标量 + 一条可微的 $\partial V/\partial\mathbf{s}$。这与"用 critic 做 baseline 降方差"是同一族思想，但目的不同：这里主要是为了"把不可微变成可微"，而不只是降方差。理解了这一层，就能明白为什么论文敢说 SHA2C "relaxes the constraint that all components of the reward signal must be dense, continuous, and differentiable"——它放松的其实不是"可微性要求"，而是"可微视界必须覆盖整个任务"这一要求。

这张图（论文 Fig. 2）证明了什么：它不是一个"模块清单"，而是在声明一种组合学主张——"环境"与"智能体"被彻底解耦，因此 $3\ \text{任务}\times4\ \text{动力学}\times3\ \text{传感器}\times4\ \text{网络}\times6\ \text{算法}$ 可以近似任意组合。组合数本身就是这篇论文的产品：它把"我提出了一个算法"变成"我提供了一个能把算法两两对比的实验台"。

8.3 Fig. 7 深读：五种算法 × 三个任务的学习曲线

论文 Fig. 7 是一个 3 列 × 3 行 的曲线矩阵：列为三个任务（位置控制 / 避障 / 竞速），行为三种视角（环境步数 → 成功率或通过门数、墙钟时间 → 成功率或通过门数、奖励曲线），五种算法（BPTT、DreamerV3、PPO、SHAC、SHA2C）。横轴量级从图上看分别是 $2\times10^{7}$（位置控制）、$10^{8}$（避障）、$2\times10^{7}$（竞速）环境步。

任务论文给出的结论（原文事实）机理分析（我的解读）
位置控制可微算法一致优于 RL 算法，样本效率甚至超过基于模型的 DreamerV3；所有算法最终都收敛到 100% 成功率任务本质是"1 秒内往哪个方向加速"，完全落在可微视界（$\approx1$ s）之内；点质量动力学让 $\partial\ell/\partial\mathbf{a}$ 又准又便宜。DreamerV3 用更少数据但更多更新（论文明确注明），在"每步数据都很贵"的设定下才占优——这里恰相反。
视觉避障SHA2C 取得最佳成功率与稳定性；与 BPTT/SHAC 使用同一个可微奖励 $R_{\text{ctrl}}$，但因 $R_{\text{goal}}$ 的引导而进一步改进、避免陷入局部最优这是"双通道"设计的直接证据：同等一阶信息下，唯一的差别是终端价值，而性能差距全部来自它。避障的局部最优（被障碍物夹住、贴墙停滞）正是纯可微损失的典型失效模式，$R_{\text{goal}}$ 提供了"必须到达"的全局拉力。
竞速采用 [7] 的进度奖励设计；未能设计出有效的可微奖励，所有可微算法表现都很差竞速需要跨数秒的全局规划 + 精确的"过门时机"，远超 1 s 可微视界；而进度奖励 $\Delta d$ 本身在"绕门"时会给出错误的局部梯度（靠近门但方向不对时仍"进步"）。这是可微方法的边界，也是论文最诚实的失败陈述。
  • 为什么"墙钟时间"那一行很重要：它把"样本效率"与"单位时间吞吐"两个维度分开。可微算法每步更贵（要保存计算图、要反传），所以在环境步数上赢、在墙钟时间上可能只是打平——这恰恰解释了为什么作者要如此执着于"$3.4\times10^{6}$ FPS"：吞吐是可微算法的生命线，因为它的每步成本天然比 PPO 高。
  • 为什么"奖励曲线"那一行要单独画：论文说明"除竞速外，报告的奖励按可微奖励的权重加权；竞速则报告 RL 的奖励信号"。这意味着跨任务比较奖励绝对值是没有意义的，只能看趋势——读图时要盯"是否收敛/是否平台化"，而不是"谁更高"。
  • 这张图证明了什么（一句话）："可微"不是一个普适的胜利，而是一个有明确适用边界的工具——在"短视界、稠密、可微"的任务上它碾压 RL；在"长视界、稀疏"的任务上它失效。而这个边界，恰好可以用 $H_{\text{eff}}\approx30$ 步来定量刻画（见 7.1.3）。

8.4 Fig. 8 深读：四种动力学（实际 3 种）的"保真度—收敛速度"权衡

Fig. 8 同样是"三任务 × 一指标"的曲线：位置控制画成功率（横轴到约 $1.5\times10^{8}$ 步）、避障画成功率（到约 $3\times10^{8}$ 步）、竞速画通过门数（$2\times10^{7}\sim8\times10^{7}$ 步）。三条曲线分别是 continuous point-mass、discrete point-mass、quadrotor dynamics。训练算法固定为"该任务上表现最好的那个"——位置控制与避障用 SHA2C，竞速用 PPO。

模型曲线形态（论文描述）为什么
continuous point-mass收敛最快、最稳9 维状态、无姿态、有一阶迟滞（$\lambda$）——既保留了最关键的相位滞后，又去掉了最刚的旋转动力学，梯度条件数最好。
discrete point-mass同样很快，但保真度更低梯形积分 + 无迟滞状态，$\partial\mathbf{p}_{t+1}/\partial\mathbf{u}_t=\frac12\Delta t^2 I$ 是常数矩阵——梯度最"干净"，但学到的策略无法表达"加速度建立过程"。
quadrotor dynamics收敛最慢、训练开销最大13 维状态 + 四元数归一化 + 角速度环 + $J^{-1}$，$\partial\mathbf{s}_{t+1}/\partial\mathbf{s}_t$ 的谱半径变化剧烈；且动作是"推力 + 角速率"，策略必须先学会内环才能谈外环——相当于把"控制"与"规划"耦合在一起学。
💡 这张图真正的贡献：把"保真度"变成了一个可测量的成本
以往论文说"我们用简化模型以加速训练"，但很少有人量化"简化到底省了多少、损失了什么"。Fig. 8 给出了一个同框架、同算法、同环境下的对照：保真度 ↑ ⇒ 收敛 ↓。它的实用价值是给出一张"选型表"——若你的任务是位置级导航（避障、拦截、航点飞行），用 pmc 就够，别用 quad；若你的任务依赖姿态（特技、精确悬停、抓取），才需要 quad，并接受更慢的收敛。但也必须指出：图中 quad 曲线在竞速任务上的表现尤其差，这与"动作空间多了 1 维、且需要先学内环"一致——论文没有给出"quad + 更长训练"能否追平的证据，因此不能断言"quad 上限更低"，只能说"quad 更贵"。

室内狭窄空间需原地转向观察点质量模型的姿态由速度方向反解，无法"停下来转一圈"换 quad 动力学（代价：收敛慢、显存高）；或在观测中显式加入"上一次动作/偏航指令"，让策略能主动控制偏航
动态障碍 / 移动目标（拦截）环境里的 30 个障碍物在本回合内静止；没有相对运动模型需要扩展 ObstacleManager 支持速度状态，并在奖励里加入"预测碰撞时间"项——这正是拦截任务的刚需
强风 / 阵风动力学里没有风扰项，只有常值阻尼 $-D\mathbf{v}$在 dynamics 里加一个 OU 过程的风速状态（可微），并把风速作为域随机化维度
依赖精确姿态的任务（特技、抓取、精确悬停）pmc/pmd 没有姿态状态；quad 虽有一阶角速度环但内环增益理想化必须用 quad，并考虑加入电机一阶滞后与桨叶效率模型
非基元几何 / 透明物体光线投射只对球/立方体/地面有解析解；深度相机对玻璃、镜面物理上就失效改用三角网格 + BVH（牺牲可微性与速度）；或引入"学习型深度补全"
需要碰撞后恢复的任务碰撞即终止，没有接触动力学接入可微接触模型（如 DiffTaichi/Dojo 的思路），或至少把"碰撞"改为"扣分但可继续"
无 NVIDIA GPU / Windows 环境全栈依赖 CUDA 与 pytorch3d、taichiCPU 可跑但吞吐掉几个量级；建议 Docker + Ubuntu 22.04 + CUDA 12

9.3 可扩展方向：按"投入—收益"排序

方向 A（低成本、高收益）：把"可微感知"真正用起来

框架已经具备可微光线投射，但观测被 detach，梯度从未流过像素。最小改动：把深度图直接作为某个损失的自变量（例如"期望深度剖面 vs 实际深度剖面"的跟踪损失），让 $\partial\ell/\partial\mathbf{p}$ 经像素回流。这能直接检验"可微渲染到底值不值"——目前这是一个没有实验回答的问题。
进阶：可微的视觉伺服——用深度图的解析梯度替代"位置误差"，做真正的 image-based visual servoing。DiffAero 已经把最难的基础设施（可微求交 + 批量并行）做好了。

方向 B（中成本、高收益）：光滑化 min/max，缓解势场局部最优

把 $\min_j d_j$ 换成 $\text{softmin}_\beta$、把 $\max_i(\cdot)$ 换成 $\text{softmax}_\beta$，可让梯度场连续；配合 alpha 的消融，能定量回答"非光滑性对避障成功率贡献多少"。这是一个纯软件、可在一张 4090 上完成的实验，适合作为后续工作的第一块基石。

方向 C（高成本、高影响）：real2sim 闭环

目前是"仿真 → 部署"的单向管线（Fig. 2 与 Fig. 5 都只有单向箭头）。若把实飞日志（位置、速度、IMU、深度）回灌，用可微仿真做系统辨识（对 $d$、$\lambda$、质量、惯量做梯度下降），就能把"凭经验标定 $\lambda$ 的随机化区间"变成"数据驱动地估 $\lambda$"。这是可微仿真相对黑箱仿真最独特的优势，而本文尚未兑现。

方向 D（中成本、中收益）：把竞速"可微化"

竞速的失败不是"可微"的失败，而是"奖励设计"的失败。一个可能的思路：以门相对坐标定义势函数 $\Phi=-\|\mathbf{p}-\mathbf{p}_{\text{gate}}\|-\kappa\,\angle(\mathbf{v},\mathbf{n}_{\text{gate}})$，并让"过门瞬间"由 critic 的终端价值吸收（即把 SHA2C 的双通道用在每一个门上，形成"分段终端价值"）。这在结构上是 SHA2C 的自然推广。

方向 E（低成本、中收益）：基准的"科学化"

补上多种子（≥5）、均值±方差、显著性检验；补上 $H_{\text{eff}}$ 与成功率的定量关系；补上 VRAM / 墙钟时间的完整报告（论文只给了柱状图）。一个自称"benchmark"的平台，其基准协议本身就是贡献。
🔬 我认为最值得做的一个方向："可微视界"作为任务难度的度量
本文的所有实验结论（位置控制可微赢、避障 SHA2C 赢、竞速可微输）都能被一个数解释：任务所需的信用分配长度与 $H_{\text{eff}}=1/(\alpha\Delta t)$ 的相对大小。如果把这个假设做成实验——固定任务、扫描 $\alpha\in\{0.5,1,2,4\}$ 与 l_rollout$\in\{16,32,64,128\}$，画出"成功率 vs $H_{\text{eff}}$"的相图——就能把"可微 RL 适合什么任务"从经验判断变成可预测的设计准则。这比再刷一个任务的成功率有价值得多。

10. 第一性原理推导

这一节不问"论文怎么做的"，而问"如果从零开始思考，为什么会必然走到这个方案"。我把推导拆成四条独立的第一性原理，它们各自指向同一个结论，合起来构成一个"收敛的论证"。

10.1 信息原理：仿真器里已经存在导数，丢弃它是信息浪费

策略梯度的两种基本估计量，本质上是"用不用模型"的分野：

Eq.(F1) —— 两种梯度估计：零阶（score function）vs 一阶（pathwise） $$ \nabla_\theta J=\mathbb{E}\Big[\underbrace{R(\tau)\,\nabla_\theta\log p_\theta(\tau)}_{\text{零阶：只需采样，方差 }\propto R^2} \Big]\;\equiv\;\mathbb{E}\Big[\underbrace{\sum_t \frac{\partial \ell}{\partial \mathbf{s}_t}\frac{\partial \mathbf{s}_t}{\partial \mathbf{a}_t}\frac{\partial \mathbf{a}_t}{\partial \theta}}_{\text{一阶：需要 }\partial\mathbf{s}/\partial\mathbf{a}\text{，方差小得多}}\Big] $$
左边是 REINFORCE / PPO 所用的估计量：它不需要环境可微，但把"奖励的随机性"整个塞进了梯度里，方差随回报的幅值平方增长。 |  右边是重参数化（reparameterization）／路径导数：它需要 $\partial\mathbf{s}_t/\partial\mathbf{a}_t$，但一旦有了它，梯度是"逐项相加"而非"乘以一个随机标量"。
第一性原理的结论：在仿真里，$\partial\mathbf{s}/\partial\mathbf{a}$ 是免费的——它由你写的物理方程决定，只是需要一次反向传播把它算出来。真实世界里你拿不到它（所以必须用零阶）；仿真里你拿得到却不用，等于主动丢弃了系统已知的全部结构信息。这就是"可微仿真"存在的全部理由。

把这个论证再推一步：既然"用导数"更好，那么越多的环节可微，能用的结构信息就越多。于是自然要问：为什么只让动力学可微？传感器也可微吗？奖励也可微吗？——DiffAero 的"全栈可微"正是这个追问的答案。反过来，哪些环节不可能可微？碰撞（指示函数）、成功/失败（离散）、真实世界的物理（不可知）——这些必须交给值函数或零阶方法。于是"可微 + 零阶"的混合不是折中，而是信息可得性的必然划分。

10.2 物理原理：欠驱动结构决定了动作空间与动力学层级

四旋翼有 6 个自由度、4 个独立输入（四个电机转速），是欠驱动系统。但"欠驱动"不等于"无法控制"——它意味着必须通过姿态间接控制平移。把 Eq.(1) 的第二式重写：

Eq.(F2) —— 推力方向即姿态：四旋翼控制的几何本质 $$ \dot{\mathbf{v}}=\mathbf{g}-c\,\mathbf{z}_B-RDR^{\top}\mathbf{v} \;\;\Longrightarrow\;\; \mathbf{z}_B=\frac{\mathbf{g}-\dot{\mathbf{v}}-RDR^{\top}\mathbf{v}}{c} $$
$\mathbf{z}_B$ = 机体 z 轴（推力方向）在世界系中的表示 |  读法：给定"想要的加速度" $\dot{\mathbf{v}}$，推力方向被唯一确定（差一个绕 $\mathbf{z}_B$ 的旋转，即偏航）。这就是为什么点质量模型可以"没有姿态"却仍然合理——姿态是加速度的从属变量，而不是独立状态。
推论 1：动作空间取"期望加速度"（pmc/pmd）在物理上是恰好充分的——它直接参数化了 $\mathbf{z}_B$；取"推力 + 角速率"（quad）则多了一层"如何转到这个姿态"的内环。
推论 2：偏航是自由的（不影响力矩平衡与平移），所以必须人为指定——这就是 point_mass_quat() 用速度 EMA 定偏航的原因，也是论文承认"室内原地转向能力缺失"的根源：自由度是冗余的，但冗余的自由度被一个固定规则锁死了。

10.3 计算原理：低分辨率下，复杂度必须正比于"看得见的东西"

渲染算法的选择不是品味问题，而是量级问题。设视场内有 $M$ 个基元、图像 $H\times W$、每个基元由 $F$ 个三角形近似：

Eq.(F3) —— 交叉点：什么时候光线投射更便宜 $$ C_{\text{raster}}\approx H W\cdot \bar F_{\text{cov}}\cdot c_{\text{frag}}+C_{\text{fixed}}, \qquad C_{\text{ray}}\approx H W\cdot M\cdot c_{\text{hit}} $$ $$ \frac{C_{\text{ray}}}{C_{\text{raster}}}\approx\frac{M\,c_{\text{hit}}}{\bar F_{\text{cov}}\,c_{\text{frag}}+C_{\text{fixed}}/(HW)} \;\xrightarrow[\ HW\to 0\ ]{}\;0 $$
$\bar F_{\text{cov}}$ = 平均每个像素被多少个片元覆盖（超采样/大三角形时会很大） |  $C_{\text{fixed}}$ = 与分辨率无关的管线固定开销（顶点处理、光栅化设置） |  关键在最后一项：当 $HW\to0$（例如 $16\times9=144$）时，$C_{\text{fixed}}/(HW)$ 爆炸，光栅化被固定开销支配；而光线投射没有固定开销，成本随像素数线性下降。
再叠加"基元化"：若场景由 30 个解析基元构成（而非 $10^{4}$ 个三角形），则 $M\,c_{\text{hit}}\ll \bar F_{\text{cov}}c_{\text{frag}}$——两个量级优势叠加，这就是 9.6× 的算术来源。
反过来：若分辨率升到 $512\times512$、场景换成三角网格，这个不等式会翻转——所以论文把"低分辨率"写进方法而不是当作妥协，是诚实的。

10.4 统计原理：Bellman 方程是一个"梯度压缩器"

为什么必须"短视界 + 终端价值"，而不能"长视界纯 BPTT"？因为后者的代价随视界指数恶化：

Eq.(F4) —— 值函数把"无限长的信用链"压成一个标量 $$ V^{\pi}(\mathbf{s}_T)=\mathbb{E}_{\pi}\Big[\sum_{k=0}^{\infty}\gamma^{k}R_{\text{goal}}(\mathbf{s}_{T+k})\Big] \;\;\Longrightarrow\;\; \underbrace{\sum_{t=0}^{\infty}\gamma^{t}R_{\text{goal}}(t)}_{\text{不可微、无限长}} \;=\;\underbrace{\sum_{t=0}^{T-1}\gamma^{t}R_{\text{ctrl}}(t)+\gamma^{T}V_\phi(\mathbf{s}_T)}_{\text{可微、有限长}+\text{一个标量}} $$
左：真实的、无限视界的目标——含大量不可微项（成功/失败），且信用链无限长。 |  右：SHA2C 的近似——前 $T$ 步用可微的稠密奖励替代，$T$ 步之后用一个学出来的标量 $V_\phi$ 替代。
为什么这是"压缩"而不是"丢弃"：$V_\phi$ 是条件期望，它保留了"未来回报的均值"这一全部一阶信息，只丢掉了"未来回报的随机性"——而随机性对期望回报的梯度贡献本来就是零均值噪声。所以这个替换在期望意义上是无损的，只引入函数逼近偏差。
代价的量化：$V_\phi$ 的误差 $\epsilon_V$ 会以 $\gamma^{T}\epsilon_V$ 的权重进入 actor 梯度；当 $T=32,\gamma=0.99$ 时 $\gamma^{T}\approx0.725$——衰减并不大，所以 critic 的精度直接决定 SHA2C 的上限。这也解释了为什么 SHA2C 要给 critic 更大的学习率（$3\times10^{-3}$ vs $1\times10^{-3}$）和全状态输入。

10.5 推导链：从"要训练一个飞行策略"到"必须自研一个可微 GPU 仿真器"

  1. 目标是什么？用神经网络把"传感器观测"直接映射为"飞行控制指令"，且要在几小时内、在消费级硬件上完成训练，并能迁移到实机。
    → 这立刻给出三条硬约束：样本量巨大（$10^{8}$ 级交互）、每步成本极低（否则小时级不可能）、仿真与实机的观测语义必须一致（否则迁移失败）。
  2. 样本量巨大 → 必须并行。单环境 30 Hz 意味着一天只能采 $2.6\times10^{6}$ 步；要 $10^{8}$ 步就得 $10^{3}$ 个环境并行。
    → 于是"每步的调度开销"成为关键：任何 host 同步都不可接受。这排除了"Python 循环 + NumPy 观测 + CPU reset"的传统 Gym 写法，指向全张量、无同步的实现。
  3. 每步成本极低 → 必须可微 + 必须便宜的渲染。若用零阶方法，达到同样性能需要 $10\sim100$ 倍样本（方差劣势）；若用光栅化渲染，低分辨率下的固定开销会吃掉大部分预算。
    → 于是"可微动力学 + 解析光线投射"成为唯一同时满足两个约束的组合。
  4. 可微 → 立刻撞上梯度病态与显存墙。长视界 BPTT 不可行；姿态动力学让雅可比谱半径剧烈变化。
    → 于是必须降维（point-mass，把姿态变成从属变量，见 Eq.(F2)）+ 软化截断（GradientDecay，见 Eq.(P2)）+ 终端价值压缩（Bellman，见 Eq.(F4)）。这三招不是三个独立技巧，而是同一个约束的三次推导。
  5. 仿真→实机 → 观测语义必须一致。若观测在世界系，实机的偏航误差会直接破坏分布；若观测函数在部署端重写，局部系变换会出现实现偏差。
    → 于是必须局部系观测（只保留偏航） + 把观测函数一起导出成 ONNX。这两条在论文里只占两句话，却是实机能飞起来的关键。
  6. 剩下什么是仿真器给不了的？接触、摩擦、风、电机、真实几何、真实光照——它们要么不可微，要么无法解析建模。
    → 于是必须接受近似（基元几何、无风、无接触），并把"近似带来的偏差"用域随机化（$d$、$\lambda$、质量、惯量、动作范围、传感器安装误差）吸收。"域随机化"在这里不是技巧，而是"可微性代价"的支付方式。
💡 一句话动机
既然在仿真里"状态对动作的导数"是免费的，那么"只采样、不求导"的强化学习就是在故意浪费已知的物理结构；而要把这份导数用起来，就必须让物理、传感、奖励同处一张 GPU 计算图——于是"重写一个仿真器"不再是工程炫技，而是"想用导数"这个决定的技术必然。

11. 核心要点

11.1 经验教训

方法论层面

  • "先建基准，再演示算法"是系统类论文最强的叙事结构。DiffAero 没有把 SHA2C 当作主贡献，而是把它当作"平台能力的存在性证明"：先证明我的平台比所有人快（Table I + Fig. 6），再证明我的平台能承载所有范式（Fig. 7 的五算法对比），最后用 SHA2C 证明"平台能催生新算法"。这三步的顺序不能颠倒——如果先讲 SHA2C，读者会问"为什么不用现有的仿真器做"；先讲平台，读者才会接受"新算法是平台的产物"。
  • 把"对比"做成"矩阵"，而不是"一对一"。Fig. 7 是 $3\ \text{任务}\times5\ \text{算法}$，Fig. 8 是 $3\ \text{任务}\times3\ \text{动力学}$。矩阵式对比的价值在于：任何单个格子的结论都可能被质疑，但整张矩阵呈现的"模式"很难被反驳——本文最重要的模式就是"可微算法在短视界任务上赢、在长视界任务上输"。
  • 诚实地报告失败，反而增强了可信度。论文明确写"我们在竞速任务上未能设计出有效的可微奖励，所以所有可微算法表现都很差"。这句话表面上削弱了"可微"的卖点，实际上让读者相信其余的成功不是挑出来的。

技术层面

  • "零拷贝"不够，要"零断图"。多数 GPU 仿真器做到"状态是张量"，但引擎边界仍然切断反向传播。DiffAero 的取舍是：凡是需要梯度的东西，必须自己用可微算子写。这条原则可以迁移到任何"仿真 + 学习"的系统（机器人、流体、电路）。
  • 梯度也需要"遗忘"。GradientDecay 用 12 行代码、一个自定义 autograd Function，就把"长视界 BPTT"的方差问题变成了一个可调的指数窗口。这个技巧极其便宜、极其通用：任何"可微 rollout 太长、梯度不稳"的场景都可以直接照搬，只需调一个 $\alpha$。
  • 双奖励通道 + 非对称 critic，是"可微 + 稀疏"的标准配方。$R_{\text{ctrl}}$ 走一阶、$R_{\text{goal}}$ 走值函数、actor 看局部观测、critic 看全状态——这四件事各自都很简单，组合起来却解决了"可微学习无法处理稀疏目标"这个根本矛盾。
  • 把"观测函数"也导出，是部署成功率的分水岭。绝大多数工作只导出策略网络，然后在部署端用 C++/Python 重写观测处理，于是训练与部署的观测出现细微偏差（坐标系、归一化、时序对齐），在高速飞行中足以致命。导出 obs_fn.onnx 这个动作，成本极低、收益极高。
  • 低分辨率是一种"主动设计"，不是妥协。$16\times9$ 的深度图去掉了纹理与细节，只保留"哪里有障碍、多远"这一决策必需的信息，同时把视觉 sim-to-real 的难度压到可控。这与"用高分辨率 + 域随机化硬扛"是两条不同的路，本文选择了前者——对资源受限的机载平台，这个选择更务实。

写作层面

  • 数字要给"两个参照系"。"orders-of-magnitude"（相对传统仿真器）与"1.8×/9.6×"（相对最强的 GPU 仿真器）分开陈述，既保住了冲击力，又经得起推敲。
  • 测量口径要主动交代。"All reported results incorporate the time and VRAM overhead associated with observation calculation, reward calculation, and environment reset operations"——这一句让所有 FPS 数字的可信度上升一个档次。
  • 公式要少而准。全文只有 6 个编号公式（4 个动力学 + 1 个梯度链 + 1 个 SHA2C 损失），每个都直接对应一处代码。相比之下，很多系统论文堆砌公式却不对应实现——本文的克制让"可复现"成为可能。

11.2 对我的研究可直接应用（UAV 视觉伺服 / 拦截 / 敏捷飞行）

我的方向可直接借用的东西具体做法 / 注意事项
视觉拦截
（移动目标）		pmc 动力学 + SHA2C 的"稠密控制奖励 + 稀疏终端价值"结构把 target_pos 从静态改为带速度的目标状态（在 reset_idx 里给目标一个随机速度，并让它每步积分）；把 $R_{\text{goal}}$ 定义为"终端脱靶量 < ε"，$R_{\text{ctrl}}$ 用"预测碰撞时间（TTC）"或"视线角速率"这类可微量。注意：拦截所需的信用分配长度通常 >1 s，需要把 l_rollout 与 alpha 一起调大，否则会重演"竞速失效"。
视觉伺服
（IBVS）		可微光线投射（球/立方体/地面的解析求交）框架已经提供 $\partial\text{depth}/\partial\mathbf{p}$，但目前没有任何损失用到它。可以构造"期望深度剖面 vs 实际深度剖面"的 $L_2$ 损失，直接做 image-based visual servoing——这是本文留下的最大空白，也是最容易出成果的切入点。
敏捷飞行
（姿态关键）		quad 动力学的完整实现（含 RateController 与四元数积分）直接复用 dynamics/quadrotor.py，但要注意：它的内环增益固定为 $[1,1,1]$，且没有电机一阶滞后。做特技飞行前建议先加电机模型（一阶低通 + 转速限幅），否则 sim-to-real 会崩。代价：quad 的收敛速度显著慢于 pmc（Fig. 8），要有耐心或先用 pmc 预训练再切换。
Sim-to-Real
落地		局部系观测（只保留偏航）+ 域随机化清单 + ONNX 双导出照抄 pmc.yaml 的随机化维度：$D\in[0.3,0.45]$、$\lambda\in[2.5,2.7]$、max_acc.xy$\in[10,20]$、max_acc.z$\in[25,40]$、vel_ema_factor$\in[0.08,0.12]$，再加传感器安装误差（$\pm3^\circ/\pm5^\circ$）。论文特别提到 $\lambda$ 的随机化区间是"凭经验标定以匹配真实四旋翼"——这一步没有捷径，必须用真机阶跃响应去标。
多机 / 集群env/position_control_multi_agent.py + algo/MASHAC.py + network/multiagents.py代码已具备，但论文没有多机的定量结果，所以这是"未验证的能力"。做集群拦截时，建议先用 appo（AsymmetricPPO，即 MAPPO 变体）建立基线，再用 mashac 对比——这本身就是一个可发表的基准缺口。
算法研究
（可微 RL）		GradientDecay + 双奖励 + 非对称 critic 的干净实现这是一个极好的消融平台：固定环境，只改 $\alpha$、l_rollout、$R_{\text{ctrl}}/R_{\text{goal}}$ 的划分，就能系统回答"可微视界多长才够"。代码结构清晰（algo/SHAC.py 只有 379 行），改造成本低。
🎯 如果只带走一件事
带走 "梯度也需要遗忘"这个想法：可微仿真的真正难点不是"能不能求导"，而是"导数能记多久、值不值得信"。任何把"长视界优化"与"可微 rollout"放在一起的研究，都必须回答"有效记忆长度是多少"这个问题——DiffAero 的答案是 $H_{\text{eff}}=1/(\alpha\Delta t)\approx30$ 步，而它的全部实验结论（谁赢谁输）几乎都由这个数字决定。这个视角比任何一个 FPS 数字都更可迁移。
