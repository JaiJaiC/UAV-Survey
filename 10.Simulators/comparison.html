训练栈对比表
把 Gazebo 放进来之后，先要区分「仿真器」和「训练栈」

Gazebo 不是 Isaac Lab 的同层竞品：它提供的是物理、传感器、ROS 2 集成与多机器人仿真， 本身不含 manager API、reward 组织、域随机化、GPU 批量训练。把它放进「训练栈」对比， 正确的问法不是「谁更强」，而是它在栈里补哪一段、还需要外接什么。

8 个栈 / 两个 Gazebo 代际 Gazebo Jetty LTS Gazebo Classic EOL 2025-01 按层比较，不按品牌站队

00先读这三句话

Gazebo 是「仿真平台」，不是「训练框架」

它负责世界、物理、传感器、ROS 2 通信与多机器人；训练循环要外接 Gym wrapper、SB3、skrl 或 PX4 SITL。

Gazebo Classic 已 EOL

Gazebo 11 于 2025-01-29 结束支持。新项目应使用 Gazebo Sim（Jetty / Harmonic），ROS 2 走 ros_gz。

「最强」取决于最贵的返工项

ROS 2 / HIL / 多机器人选 Gazebo；人形大规模 RL 选 Isaac Lab；快速试错选 Playground / mjlab。

03Gazebo 到底补哪一段？

它强在「系统集成」

  • ROS 2 原生：ros_gz bridge、launch、composition、QoS 都能直接用。
  • SDF / URDF 资产与 Fuel 模型库，适合多机器人、复杂场景、传感器仿真。
  • PX4 / ArduPilot 的 SITL/HITL 默认后端之一，无人机与移动机器人验证链路成熟。
  • 插件机制让传感器噪声、执行器模型、环境控制可以按需扩展。

它不负责「训练循环」

  • 没有 manager API、reward 组合、curriculum、域随机化的一等抽象。
  • 物理默认 CPU，缺少 GPU tensorized 批量环境；大规模 RL 吞吐不占优。
  • 没有内置批量渲染 / 可微物理 / 多物理耦合。
  • 训练要外接 Gym wrapper、SB3、skrl、RLlib，或直接用 PX4 的 RL 工具链。
一句话 Gazebo 更像是「ROS 2 的操作系统 + 物理/传感器外设」，Isaac Lab 更像是「机器人学习的 IDE + 运行时」。 把两者放在同一张表里，是为了看清接口，而不是为了选一个「全能冠军」。
