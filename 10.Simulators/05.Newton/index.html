Layer 05 · 底层物理引擎 / 连接器

Newton
它不是一个新环境库，而是底座之间的接口层

如果把 Newton 写成「英伟达又发布了一个物理引擎」，就会漏掉它真正的位置。它建立在 NVIDIA Warp 之上， 以 MuJoCo Warp 为主要后端，用 OpenUSD 表达场景与资产，强调可微与可扩展，并由 Linux 基金会治理。 它连接的是几个原本各有重心的生态：USD、Warp、MuJoCo、Isaac Lab。短期它不会替代谁， 但会改变「物理仿真如何接入学习系统」的写法。

Disney Research · Google DeepMind · NVIDIA Linux Foundation Apache-2.0 Isaac Lab 3.0 一等后端 物理引擎层

01先把它放对位置

Newton 不是一个「拿来就能跑任务」的框架。它没有 Isaac Lab 的任务管理器，也没有 Playground 的环境库； 它提供的是物理世界的计算底座：刚体、关节、接触、可变形体、颗粒、布料、线缆， 以及把这些求解器组织起来的场景与状态表示。

它和上层框架的关系，更像「编译器后端」和「语言前端」：Isaac Lab 3.0 把 Newton 作为可选的物理后端， 通过 physics=newton_mjwarp 这样的预设切换；同一个任务可以跑在 PhysX 上，也可以跑在 Newton 上， 并提供了 PhysX↔Newton 的策略迁移验证。这种「同一任务、两个物理引擎」的能力，是 sim2sim 真正有意义的前提。

一句话定位 Newton 是物理引擎层的连接器：向下接 Warp 的 GPU 计算，向上接 Isaac Lab / MuJoCo 生态， 向外接 OpenUSD 的资产与场景表达。

Newton 的技术报告与 README 把关键点写得很清楚：它扩展并泛化了 Warp 已弃用的 warp.sim 模块， 把 MuJoCo Warp 集成为主要后端，强调 GPU 计算、OpenUSD、可微性和用户自定义扩展。 「可微」不是一句口号：它意味着系统辨识、设计优化、控制优化和数据效率这些方向，可以在物理层直接获得梯度， 而不必把仿真当成黑箱。

03四个值得关注的信号

1. 治理结构：Linux 基金会

Newton 由 Disney Research、Google DeepMind、NVIDIA 共同发起，由 Linux Foundation 管理。 这不是普通的「公司开源项目」：它试图把物理引擎变成多方共同治理的基础设施。 对担心单一厂商锁定的团队，这是一个积极信号；但治理的开放不等于技术的成熟，两者要分开看。

2. 多物理：从刚体走向软体、颗粒、布料、线缆

人形机器人早晚会遇到全身接触、灵巧手细粒度接触、移动操作中的推拉拖挤，以及布料、软体、颗粒材料、触觉。 这些东西如果都靠外层域随机化硬盖，会越来越难受。Newton 的 MPM、VBD、布料、线缆、软体示例， 说明它在为这些任务做准备——虽然成熟度还参差。

3. Isaac Lab 3.0：从「实验性集成」到「一等后端」

Isaac Lab 3.0 的 isaaclab_newton 支持 MuJoCo-Warp、VBD、MPM、Kamino 等求解路径， 并且可以在不安装 Isaac Sim 的 kit-less 模式下运行。3.0 GA 还提供了 PhysX↔Newton 的策略迁移指南与验证示例。 这和早期 beta 阶段「只支持经典 RL 和平地 locomotion」的状态相比，是一个实质性的进展。

4. 它把「物理保真度」变成可替换变量

过去选框架，往往等于选物理引擎；物理引擎又被绑在平台上。Newton 的方向是： 任务 API 不变，物理后端可换。这会让「用哪个求解器」从架构决策变成一个实验变量—— 对 sim2real 研究，这是很重要的自由度。

04现在不必神化，但一定要盯

  • 年轻。 API、求解器覆盖、文档都在快速变化；Isaac Lab 3.0 的 release notes 仍把部分功能标为 backend-specific 或 unsupported。
  • 硬件门槛。 GPU 路径需要 NVIDIA Turing 及以上（compute capability 7.5+）与较新的驱动；macOS 只能 CPU 运行。
  • 求解器差异是真实的。 MuJoCo-Warp、XPBD、Featherstone、VBD 的行为不同，策略迁移不是「换个 flag 就等价」。
  • 生态仍在建设。 相比 PhysX / MuJoCo 数十年的积累，Newton 的资产、教程、社区答案都还少。
选型提醒 如果明天只是训练一个普通速度跟踪策略，Newton 未必是第一选择。稳定、资料多、调试顺、能和现有代码接起来， 可能比「更新的物理引擎」更重要。Newton 的价值更适合放在 6–18 个月的时间尺度上看。

05什么时候该看它

适合关注

  • 任务开始涉及复杂接触、软体、布料、颗粒、线缆
  • 需要可微物理做系统辨识、设计优化、控制优化
  • 想在 Isaac Lab 内做 PhysX↔Newton 的 sim2sim 验证
  • 希望物理层由多方治理、避免单一厂商锁定
  • 做多物理耦合的研究型任务

暂缓

  • 需要稳定、资料丰富、开箱即用的 locomotion baseline
  • 团队没有 NVIDIA GPU 或较新的驱动
  • 任务只涉及简单刚体接触，现有引擎已足够
  • 不能接受 API 与求解器行为的快速变化
